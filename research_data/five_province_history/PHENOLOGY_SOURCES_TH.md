### ไฟล์และวิธีรันซ้ำ

- `disaster_village_annual.csv` — แถวหมู่บ้านต้นทางของ 5 จังหวัด รักษาช่องว่าง/คอลัมน์ปี/รหัสทรัพยากร/เลขบรรทัดเพื่อย้อนตรวจ
- `disaster_province_annual.csv` — 60 แถว จังหวัด–ปี–ชนิดภัย มีจำนวนช่องว่าง จำนวนแถวกันออก และผลรวมหมู่บ้าน–ครั้งที่รายงาน ไม่ถือว่าครบทั้งปี
- `disaster_news_index.csv` — ดัชนีข่าว 143 รายการ ไม่ส่งออกพิกัดหรือข้อมูลส่วนบุคคลในเนื้อหาข่าว
- `disaster_events_reviewed.json` — 7 รายงานที่ตรวจวันที่/อำเภอ/หน่วยความเสียหายแล้ว วันสิ้นสุดที่ไม่รู้ยังเป็น null
- `disaster_harvest_overlap.csv` — 237 แถวเทียบวันสังเกตเหตุกับเดือนผลผลิตจริง และอายุสมมติ 120/130/140/150 วัน สัดส่วน `*_candidate_days_pct` คือสัดส่วน **วันเก็บเกี่ยวที่เป็นไปได้** ไม่ใช่สัดส่วนสวนเสียหาย ใช้เพื่ออ่านย้อนหลัง ไม่ใช่ predictor ที่รู้ล่วงหน้า
- `disaster_source_review.json` — URL คำขอทุกหน้า hash ต้นฉบับ พารามิเตอร์ค้น และข้อจำกัด สำเนาดิบอยู่ใน ignored `evidence/` ไม่เผยแพร่ข้อมูลส่วนบุคคลจากรายงานซ้ำ

รัน `python tools/prepare_ddpm_disasters.py` จาก root ใน environment ตาม requirements หลักได้ ใช้ `openpyxl` ที่มีอยู่แล้วเพื่ออ่านต้นฉบับภัยแล้ง XLSX ปี 2567–2568; ทดสอบด้วย `python -m unittest discover -s tests -p test_ddpm_disasters.py -v` ตารางนี้ยัง **ไม่ถูก join เข้า training หรือหน้าเว็บอัตโนมัติ** เพราะความครบถ้วนและพื้นที่สวนที่ได้รับผลกระทบยังไม่ยืนยัน

การเทียบวันรองรับเหตุสั้นเพียงวันเดียว และเหตุปลายปีที่อาจทับรอบผลปีถัดไป เช่น ช่วงผลสมมติของ cohort ก.พ. 2568 อาจมีเหตุ ธ.ค. 2567; เหตุหลังเก็บเกี่ยวไม่ใช้ไปอธิบายการสูญเสียของผลที่เก็บไปแล้ว ยังต้องเพิ่มอากาศสุดขั้วรายวัน/รายชั่วโมง เช่น Tmax วันสูงสุด วันร้อนต่อเนื่อง 2–3 วัน ฝนสะสม 3/7 วัน และลมกระโชก โดยเกณฑ์ร้อนเป็นสมมติฐานทดลอง ไม่ใช่ค่าพิสูจน์การร่วงทุเรียน

## ภัยแล้งจาก ปภ. เพิ่ม 9 ตุลาคม 2569

ดาวน์โหลด [สถิติรายปีการเกิดภัยแล้ง dpm-gd028](https://catalog.disaster.go.th/dataset/dpm-gd028) ต้นฉบับ CSV ปี 2562–2566 และ XLSX ปี 2567–2568 แล้ว คัดเฉพาะ 5 จังหวัดได้ **2,655 ระเบียน** ใน `drought_area_records.csv` พร้อม URL/ปีชุดรายงาน/แผ่นงาน/แถวต้นทาง/hash ใน `disaster_source_review.json` ไม่ใช่แผนที่เสี่ยงภัยแล้ง `dpm-gd016`

| จังหวัด | ปีชุดรายงานที่พบระเบียน | จำนวนระเบียนที่คัด |
| --- | --- | ---: |
| จันทบุรี | 2563, 2566, 2567 | 403 |
| ศรีสะเกษ | 2562, 2563, 2567, 2568 | 666 |
| อุตรดิตถ์ | 2562, 2563, 2566 | 260 |
| สุราษฎร์ธานี | 2567 | 180 |
| ชุมพร | 2566, 2567 | 1,146 |

แถวปี 2562–2567 เป็นรายการพื้นที่ ส่วนปี 2568 เป็นสรุประดับจังหวัด (ศรีสะเกษ 1 แถว) **จำนวนแถวนี้จึงไม่ใช่จำนวนครั้งภัยแล้ง** และไม่บวกรวมเป็นความเสียหาย ไม่เติมจังหวัด–ปีที่ไม่มีระเบียนให้เป็นศูนย์ ปีในชื่อชุดรายงานอาจมีวันเกิดเหตุปลายปีก่อนหน้า จึงเก็บ `source_year_be` และ `incident_date` แยกกัน

897 ระเบียนมีวันเกิดและวันยุติสถานการณ์จากคอลัมน์ต้นฉบับปี 2562–2563; วันลงนามปิดภัย/ประกาศยุติในปีหลังเก็บเป็น `administrative_closure_date` ไม่ใช้แทนวันสิ้นสุดฝนทิ้งช่วงหรือความเครียดต้น **คอลัมน์อังกฤษ Agriculture (Acres) ของ XLSX มีหัวไทยระบุไร่** จึงรักษาหน่วยไร่ตามหัวไทย ไม่คูณแปลงเอเคอร์ ตัวเลขนี้รวมทุกพืช ไม่ใช่พื้นที่เสียหายทุเรียน

ข่าวแล้งที่ค้นได้มี 5 รายการศรีสะเกษ และ 12 รายการสุราษฎร์ธานีในปี 2020 หลายรายการเป็นส่งน้ำ/ติดตามการช่วยเหลือ ไม่ใช่เหตุใหม่ทุกข่าว เช่น [รายงานเวียงสระ 15 เม.ย. 2563](https://dpmreporter.disaster.go.th/portal/disaster-news/1454) กล่าวถึงฝนทิ้งช่วงตั้งแต่ ธ.ค. 2562 และพื้นที่เกษตรราว 3,000 ไร่ ไม่ได้ระบุสูญเสียทุเรียน 3,000 ไร่ วันเริ่มระดับเดือนนี้ยังไม่ถูกบังคับให้เป็น 1 ธ.ค. หรือเติมระยะต่อเนื่องทุกวันในโมเดล

## API ดาวเทียมฟรีสำหรับ NDVI — ตรวจ 9 ตุลาคม 2569

| แหล่ง | การเข้าถึงและบทบาทในโปรเจกต์ |
| --- | --- |
| [NASA ORNL TESViS REST](https://modis.ornl.gov/data/modis_webservice.html) | ทดลองเรียกสำเร็จโดยไม่ใช้คีย์/บัญชี; MOD13Q1 มี NDVI, pixel reliability และ VI Quality แบบ 16 วัน ความละเอียด nominal 250 ม. ดึงช่วง 2003–2025 สำหรับการทดลองต่อไร่เดิม |
| [Element 84 Earth Search](https://github.com/Element84/earth-search) | STAC ค้นภาพฟรี; ทดสอบ Sentinel-2 Collection 1 L2A จุดจันทบุรี ม.ค. 2024 ได้ 13 scenes เลือก assets HTTPS ที่ไม่เป็น requester-pays; ยังไม่ได้ใช้แทน MODIS ในการเทรน |
| [Microsoft Planetary Computer](https://planetarycomputer.microsoft.com/docs/) | STAC public ไม่ต้องมีบัญชี ข้อมูล Azure ต้องใช้ SAS ชั่วคราวจาก API ลงนามและอาจถูก throttle; ไม่ใช่ API key สวนของผู้ใช้ ใช้เป็นทางเลือกสำหรับ Sentinel-2/MODIS |
| [Google Earth Engine](https://developers.google.com/earth-engine/guides/access) | เหมาะกับการสรุปหลาย polygon แต่ต้องมี Cloud project และยืนยันสิทธิ์ noncommercial; มี [โควตาฟรีรายเดือน](https://developers.google.com/earth-engine/guides/noncommercial_tiers) ไม่ใช่ฟรีไม่จำกัด และงาน commercial ใช้เงื่อนไขอีกแบบ |

NDVI เป็นดัชนีความเขียวจากการสะท้อนแสง **ไม่ใช่ค่าการสร้างอาหาร ความพร้อมติดผล หรือหลักฐานแล้งโดยตรง** ดูวิธีและ QA ของ [MODIS VI](https://modis-land.gsfc.nasa.gov/pdf/MOD13_User_Guide_V61.pdf) ซึ่งกล่าวถึง EVI สำหรับพืชหนาแน่นด้วย หากพัฒนาเชิงสวน ควรใช้ขอบเขตแปลงที่ยืนยันแล้วและ Sentinel-2 NDVI/NDMI โดยกรอง SCL เมฆ–เงาเมฆ ปรับ scale/offset ตามรุ่นภาพ และบันทึกสัดส่วนพื้นที่เห็นจริง ไม่เฉลี่ยป่า/ข้าว/ยางทั้งจังหวัดแล้วเรียกสุขภาพทุเรียน

ตัวดาวน์โหลด `tools/fetch_modis_ndvi.py` ใช้จุดอ้างอิงเดิมจาก `reference_points.csv` รอบจุด ±1 กม. เก็บกริดจริงและ QA ทุก composite raw ไม่ถูกเขียนทับและอยู่ใน ignored `evidence/` ค่าว่างไม่เป็น 0 สูตรการสรุปผ่าน `tools/compare_harvest_stage_yield.py --ndvi` ใช้ข้อมูลระยะเดิมจากชุดฝึก ไม่ใช้ผลผลิตรายเดือนปีทดสอบเลือกฤดู รายละเอียด/ผลเทรนอยู่ใน [คู่มือ training](training/README_TH.md)
