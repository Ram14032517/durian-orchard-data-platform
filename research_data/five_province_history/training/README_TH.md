## ลองอ่านใน Jupyter

```python
import json
from pathlib import Path
import pandas as pd

folder = Path(r'C:\project\research_data\five_province_history\training')
df = pd.read_csv(folder / 'monthly_model_panel.csv', dtype={'province_code': str})
meta = json.loads((folder / 'manifest.json').read_text(encoding='utf-8'))
usable = df[df.eligible_for_baseline.eq(1)].copy()
train = usable[usable.suggested_split.eq('train')]
valid = usable[usable.suggested_split.eq('validation')]
test = usable[usable.suggested_split.eq('test')]
X_train = train[meta['feature_allowlist']]
y_train = train[meta['target']]
print(df.shape, train.shape, valid.shape, test.shape)
```

## ก่อนเทรนจริง

### ผลทดลองรอบแรก

`python tools/train_monthly_production.py` ใช้ numpy และ pandas เรียนรู้เฉพาะ train ถึง 2021 เลือก alpha จาก [1,10,100] ด้วย validation 2022–2023 และทดสอบ 2024–2025 ไม่ fit ซ้ำบน validation และไม่เลือกโมเดลจาก test

ไฟล์ `model_metrics.csv` แสดง MAE หน่วยตันต่อจังหวัด–เดือนรวมและรายจังหวัด, `model_predictions.csv` เก็บ actual/predicted ทุกแถว, `model_validation.csv` เก็บการเลือก alpha และ `model_baseline.json` เก็บพารามิเตอร์ที่ fit แล้ว

| โมเดล | Validation MAE (71 แถว) | Test MAE (75 แถว) |
|---|---:|---:|
| ค่ามัธยฐานจังหวัด–เดือน | 18,406.01 | 15,271.28 |
| Ridge จังหวัด–เดือน | 17,866.53 | 14,685.26 |
| Ridge จังหวัด–เดือน + อากาศเดือนก่อน | 17,994.19 | 15,283.82 |

เลือก Ridge จังหวัด–เดือนจาก validation ผลทดลองนี้ยังไม่พบว่าเพิ่มอากาศเดือนก่อนแล้วดีขึ้น **ไม่ได้พิสูจน์ว่าอากาศไม่มีผล** อาจต้องเพิ่มระยะสะสมอากาศ พื้นที่ให้ผล การจัดการ และข้อมูลมากกว่านี้ก่อน ส่วน test นี้ถือว่าเปิดดูแล้ว หากพัฒนาโมเดลต่อควรใช้ rolling validation และกันชุดทดสอบใหม่ ไม่จูนตาม test ชุดนี้

ค่าคลาดเคลื่อนยังสูงและประเมินเฉพาะเดือนที่มีรายงานผลผลิต ห้ามอ้างเป็นความแม่นยำทั้งปี/รายสวน หรือใช้จำลองอุณหภูมิเพิ่มแล้วสรุปผลเชิงเหตุโดยตรง

### ผลเทียบตัวแปรกับผลผลิตต่อไร่รายปี (สำรวจ ไม่ใช่หาสาเหตุ)

`annual_yield_windows_panel.csv` มีคอลัมน์ `province_code`, `province_name`, `year_ce`, `anchor_month`, `yield_kg_rai` และ `w1_` ถึง `w6_` สำหรับอากาศสะสมก่อนเดือนอ้างอิง:

- `anchor_month` คือเดือนที่ผลผลิตรวมสูงสุดจากระเบียนฝึกถึง 2021 กำหนดคงที่แยกจังหวัด
- `w1_` คือ 1 เดือนเต็มก่อน anchor; `w6_` คือรวม 6 เดือนเต็มก่อน anchor **เป็นหน้าต่างสะสม ไม่ใช่ค่าเดือนที่ 6 เพียงเดือนเดียว** เช่น anchor พฤษภาคม 2025 → w1 เมษายน 2025, w6 พฤศจิกายน 2024–เมษายน 2025
- `temperature_c`, `humidity_pct`, `solar_mj_m2_day` เฉลี่ยตามจำนวนวันจริง; `rain_mm` รวมฝนทั้งหน้าต่าง หากอากาศตัวใดไม่ครบวันจะเก็บ window นั้นเป็น missing
- `yield_kg_rai` = ผลผลิตตัน × 1000 / พื้นที่ให้ผลไร่ เป็น target รายปีระดับจังหวัด

อ่านชุดรายปีใน Jupyter แล้วแยกปีด้วย:

```python
annual = pd.read_csv(folder / 'annual_yield_windows_panel.csv', dtype={'province_code': str})
features = ['province_code', 'year_ce', 'w6_temperature_c', 'w6_rain_mm',
            'w6_humidity_pct', 'w6_solar_mj_m2_day']
annual = annual.dropna(subset=['yield_kg_rai', *features])
train = annual[annual.year_ce <= 2021]
valid = annual[annual.year_ce.between(2022, 2023)]
test = annual[annual.year_ce.between(2024, 2025)]
# province_code เป็นหมวดหมู่: one-hot ก่อน fit และ fit preprocessing จาก train เท่านั้น
```

รัน `python tools/analyze_annual_yield_windows.py` แล้ว `python tools/compare_annual_yield_features.py` จากรากโปรเจกต์ ได้ `annual_yield_feature_comparison.json` (145 จังหวัด–ปี, 5 จังหวัด) เป้าหมายคือ สศก. ผลผลิตรวมตัน × 1000 / พื้นที่ให้ผลไร่ของปีนั้น ทุกพันธุ์รวมกัน โมเดล Ridge ทุกตัวมีจังหวัดและแนวโน้มปีเป็นฐาน; เพิ่มอากาศทีละตัวหรือครบ 4 ค่า โดยใช้ค่าเฉลี่ยอุณหภูมิ/ความชื้น/แสง และฝนรวม 6 เดือนเต็มก่อนเดือนเก็บเกี่ยวอ้างอิงที่กำหนดจากข้อมูลฝึกถึง 2021 ไม่ใช่ระยะจริงของต้นในแต่ละปี

| ตัวแปรเพิ่มเติม | Validation MAE 2022–23 | Test MAE 2024–25 |
|---|---:|---:|
| ไม่มี (ฐานจังหวัด + แนวโน้มปี) | 297.6 | 182.6 |
| อุณหภูมิ | 284.6 | 195.7 |
| ฝน | 297.9 | 182.9 |
| ความชื้น | 262.9 | 190.2 |
| แสง | 294.5 | 177.3 |
| อากาศ 4 ค่า | 240.0 | 212.0 |

หน่วย MAE คือ กก./ไร่ (ต่ำกว่าดีกว่า) แต่ test มีเพียง 10 จังหวัด–ปี และการเปิดดูหลายตัวแปรบนชุดเดียวเป็นการสำรวจ ไม่ควรเลือกโมเดลสุดท้ายจาก test นี้ แบบรวม 4 ค่าให้ผล validation ดีกว่าฐานแต่ test แย่กว่า; แสงเดี่ยวดีขึ้นจากฐานบน test เพียง 5.3 กก./ไร่ จึงยังสรุปว่าตัวใดเป็นตัวขับหรือ “ทำให้” ผลผลิตลดไม่ได้ ลมมีในกราฟรายวัน แต่ยังไม่อยู่ใน panel โมเดลรายปี และลมเฉลี่ยไม่ใช่ลมกระโชกจากพายุ ยังไม่มีการควบคุมพันธุ์ อายุ/ระยะต้น การให้น้ำ โรค จำนวนผลร่วง และสภาพอากาศรายสวน/รายอำเภอ ต้องเก็บข้อมูลเหล่านี้และทดสอบข้ามปีเพิ่มเติมก่อนข้อสรุปเชิงสาเหตุ

| ย้อนช่วงระยะผล อายุสมมติ 150 วัน | 227.2 | 209.5 |

หน่วย MAE คือ กก./ไร่; แถวละหนึ่งจังหวัด–ปี แบบจำลองระยะผลใช้ฝนก่อนดอกและช่วงผล รวมถึงแสง/อุณหภูมิในช่วงอายุผลที่กำหนด ฤดูสามเดือนคงที่ของแต่ละจังหวัดเลือกจากเดือนผลผลิตสูงสุดในข้อมูลฝึกถึงปี 2021 เท่านั้น แล้วใช้หน้าต่างเดิมกับ validation/test ไม่ใช้การกระจายผลผลิตรายเดือนปีเป้าหมายเลือกอากาศ อายุ 120 วันชนะบน validation ในรอบสำรวจนี้ แต่ผล test ดีขึ้นจากฐานเพียง 18.2 กก./ไร่ และมีเพียง 10 แถว จึงเป็นสมมติฐานที่น่าทดลองซ้ำ ไม่ใช่หลักฐานว่าอายุผลจริงของทุกจังหวัดคือ 120 วัน

**ข้อจำกัดสำคัญ:** ปี 2567–68 ถูกเปิดดูระหว่างการสำรวจแล้ว จึงไม่ใช่ชุดยืนยันผลที่เป็นอิสระ; แบบจำลองเป็นการย้อนอากาศจริงตามฤดูคงที่ ไม่ใช่การใช้ forecast ที่รู้ได้ก่อนเก็บเกี่ยว; ผลผลิตรวมทุกพันธุ์แต่ใช้อายุผลเป็นสถานการณ์; อากาศยังเป็น NASA POWER จุดเดียวต่อจังหวัด ไม่ได้เฉลี่ยถ่วงด้วยสวนที่ให้ผลจริง; และข้อมูลชุดนี้ยังไม่ได้ควบคุมการให้น้ำ อายุ/พันธุ์ต้น โรค หรือการจัดการ ผลที่ดีขึ้นเป็นสัญญาณให้ทดสอบซ้ำ ไม่ได้พิสูจน์เหตุหรือยืนยันว่าโมเดลพร้อมใช้งาน การทดลองฉบับแรกที่ใช้เดือนเก็บเกี่ยวจริงของปีเป้าหมายถูกยกเลิก เพราะเสี่ยงให้ข้อมูลรั่วเข้า feature; ตารางนี้มาจากเวอร์ชันที่กำหนดฤดูด้วยข้อมูลฝึกเท่านั้น

### ทดลองหลายปีแบบ nested rolling (8 ตุลาคม 2569)

รอบนี้ทดสอบสมมติฐานว่าอากาศที่ย้อนตามงวดเก็บเกี่ยวช่วยอธิบายผลผลิตต่อไร่ได้มากกว่าประวัติผลผลิตอย่างเดียวหรือไม่ โดยใช้ข้อมูลจริง 110 จังหวัด–ปี (2004–2025) ไม่มีการสร้างผลผลิตรายชุดดิน หรือถือว่าสถานการณ์อายุผลเป็นตัวอย่าง target ใหม่

วิธีที่นำมาประยุกต์จากงานวิจัยต้นฉบับ:

- [Meroni และคณะ: ML กับข้อมูลผลผลิตขนาดเล็ก](https://arxiv.org/abs/2104.13246) ใช้การจูนและประเมินแยกปีซ้อนสองชั้น พร้อมฐานง่าย ๆ; ในโปรเจกต์นี้เปลี่ยนจาก leave-one-year-out เป็นเดินไปข้างหน้าเท่านั้น ไม่ใช้ปีอนาคตฝึกปีอดีต
- [Morales และ Villalobos: ทำนายอดีตกับอนาคต](https://doi.org/10.3389/fpls.2023.1128388) สนับสนุนการประเมินตามเวลาและเปรียบเทียบโมเดลหลายแบบ งานต้นฉบับใช้ข้อมูลจำลองข้าวสาลี/ทานตะวัน จึงยืมเฉพาะวิธีทดสอบ ไม่ยืม target หรือสัมประสิทธิ์มาแทนทุเรียน
- [Srivastava และคณะ: อากาศ ดิน และระยะพืช](https://doi.org/10.1038/s41598-022-06249-w) เป็นแนวทางสำหรับสรุปอากาศตามเวลา/ระยะพืชและถ่วงพื้นที่เกษตร แต่รอบนี้ยังไม่ได้ทำค่าเฉลี่ยเชิงพื้นที่สวนที่ให้ผล งานทุเรียนยังไม่มีข้อมูลระดับแปลงและระยะจริงแบบนั้น

**ขั้นตอนทดสอบ:** กันปี 2014–2025 ทีละปี รวม 12 รอบ × 5 จังหวัด = 60 ระเบียนทดสอบ จูนในสามปีก่อนปีทดสอบ โดยแต่ละรอบย่อยเรียนจากปีก่อนหน้านั้นเท่านั้น เลือกฤดูสามเดือนจากผลผลิตรายเดือนในอดีตของรอบฝึก ไม่ใช้เดือนเก็บเกี่ยวปีทดสอบ หลังเลือกค่าจูนจึง fit ใหม่ด้วยข้อมูลทุกปีก่อนปีทดสอบ การเลือกอายุ 120/130/140/150 วันและ alpha/ขนาดใบต้นไม้เกิดใน inner validation เท่านั้น

ทุกโมเดล Ridge/ต้นไม้มีตัวแปรจังหวัดและปี แบบที่ชื่อ `lag_yield` หรือมีอากาศเพิ่มผลผลิตต่อไร่ปีก่อนด้วย; Random Forest และ Gradient Boosting มีคู่ไม่มีอากาศเพื่อแยกประโยชน์ของการเปลี่ยนชนิดโมเดลออกจากการเพิ่มอากาศ จำกัดการค้นหาไว้ 43 configurations ต้นไม้ใช้ random seed 42 ไม่เพิ่มจำนวนตัวเลือกตามคะแนน outer test

### แนวทางพัฒนาต่อ

1. เริ่ม baseline ค่ากลางผลผลิตแยกจังหวัด–เดือน โดย fit จาก train เท่านั้น แล้วเปรียบเทียบโมเดลอากาศด้วย MAE หน่วยตันและรายจังหวัด ห้ามสุ่มแถวข้ามปี ให้จูนเฉพาะ validation และกัน test ไว้
2. แยก missing ออกจาก 0 อย่าเติมทุกเดือนนอกฤดูเป็น 0 อัตโนมัติ ชุดที่มี target อาจเน้นเฉพาะฤดูเก็บเกี่ยว จึงยังสรุปความแม่นยำทั้งปีไม่ได้
3. ใช้เฉพาะ feature_allowlist อย่านำผลผลิตปีเดียวกัน ตัวแปรเป้าหมาย หรือข่าวที่เผยแพร่ภายหลังมาป้อนเป็น feature อากาศเดือนก่อนช่วยลดการมองอนาคต แต่ข้อมูลนี้เป็นฉบับย้อนหลังที่ปรับปรุงแล้ว ยังไม่รู้วันเผยแพร่/ความล่าช้าของทุกแหล่ง จึงไม่ใช่ backtest การพยากรณ์ใช้งานจริง
4. ปฏิทินกรมวิชาการเกษตรเป็นกรอบภูมิภาค ไม่ใช่ label ระยะจริงรายสวน จึงเก็บแยกและไม่ใช้เป็นคำตอบเทรน ข่าวไม่มีระเบียนไม่ได้แปลว่าไม่มีเหตุ
5. ตารางดินเป็นข้อมูลเชิงพื้นที่ ห้าม join จังหวัดแล้วทำซ้ำยอดผลผลิตให้ดินทุกชุด ยังไม่มีผลผลิตราย polygon ดินให้ฝึก supervised model
6. ชุดนี้ไม่มีข้อมูลเซนเซอร์สวน ไม่ปะปน indoor/outdoor หรือช่วง gateway ค้าง การนำเซนเซอร์มารวมต้องทำ QC อีกชุดก่อน และห้ามเติมอากาศค้างเป็นค่าจริง
7. ผลผลิตรวมเกี่ยวกับพื้นที่ให้ผล อายุ พันธุ์ และการจัดการด้วย โมเดลสัมพันธ์อากาศกับผลผลิตไม่ได้พิสูจน์สาเหตุหรือแนะนำการงดน้ำโดยตรง

## เพิ่ม NDVI จริงใน benchmark เดิม — 9 ตุลาคม 2569

ใช้ [NASA ORNL TESViS REST API](https://modis.ornl.gov/data/modis_webservice.html) ไม่ต้องใช้คีย์/บัญชี ดึง MOD13Q1 ตั้งแต่ 2003–2025 เพื่อครอบคลุมช่วงก่อนดอกของปี 2004 ที่ย้อนไปปี 2003 ช่วงทดสอบยังเหมือนเดิมคือ 2014–2025 จำนวน 60 จังหวัด–ปี ไม่ได้ลดข้อมูลผลผลิตให้เฉพาะปีที่ดาวเทียมเห็นชัด และไม่ได้สร้าง target สุขภาพต้นขึ้นเอง

**กำหนดวิธีก่อนดูคะแนน:** เพิ่มสองตัวแปร NDVI ให้คู่ Ridge ทั้งปี, Ridge ตามระยะ, Random Forest ตามระยะ และ Gradient Boosting ตามระยะ ใช้ข้อมูลฝึก/validation/test เดียวกับคู่ไม่มี NDVI ในแต่ละ fold รวม 74 configurations (เดิม 43 + NDVI 31) การเลือกฤดู อายุ 120/130/140/150 และ hyperparameters ทำจากอดีตของ fold เท่านั้น การทดสอบทั้ง 12 ปีเคยถูกใช้สำรวจแล้ว จึงไม่เรียกคะแนนนี้เป็น holdout ยืนยันใหม่

การเตรียม NDVI:

1. รอบจุดอ้างอิงเดิมแต่ละจังหวัด ±1 กม. เก็บกริด actual cell ≈231.7 ม. และ nominal resolution 250 ม. ตาม API เป็น **context patch รวมพืชอื่น ไม่ใช่พื้นที่สวนทุเรียน/ค่าเฉลี่ยจังหวัด** ไม่มีน้ำหนักเนื้อที่ให้ผลและยังแยกสวนใหม่ไม่ได้
2. กรอง `pixel_reliability=0`, MODLAND QA=0, land class=1 ตัด aerosol สูง เมฆข้างเคียง/เมฆผสม หิมะและเงาออก ค่า raw -3000 เป็น fill; raw NDVI ที่รับได้ -2000 ถึง 10000 คูณ scale 0.0001 ครั้งเดียว ค่า 0 ที่ผ่าน QA คงเป็น 0
3. ต้องมีพิกเซลผ่าน QA ≥20% จึงสรุป mean/p10 ของ patch การเปลี่ยนชุดพิกเซลที่เห็นชัดทำให้พื้นที่ตัวอย่างไม่คงเดิมทุกงวด เก็บ `good_pixel_pct` และสถานะไว้ตรวจ ไม่ใส่ความเขียว 0 ให้ช่วงเมฆ
4. ตัวแปรทั้งปี: `ndvi_annual_mean` (ถ่วงระยะงวดที่เห็นจริง) และ `ndvi_annual_p10` (เปอร์เซ็นไทล์ 10 ของ composite means ที่ผ่าน QA) ระดับปีเห็นข้อมูลหลังเก็บเกี่ยวด้วย เหมาะแค่ retrospective comparison
5. ตัวแปรระยะผล: `ndvi_pre_bloom_mean` ใน 90 วันก่อนดอกสมมติ และ `ndvi_fruit_mean` ตั้งแต่ดอกสมมติถึงเก็บเกี่ยว ถ่วงด้วยจำนวนวันที่ **งวด composite** ทับหน้าต่างของวันเก็บที่เป็นไปได้ ไม่ใช่การเพิ่มข้อมูลวัดรายวัน การใช้ composite ที่ทับบางส่วนอาจเห็นข้อมูลนอกขอบหน้าต่าง ไม่ใช่ forecast ที่ออกก่อนเก็บเกี่ยว

### ผลเทรน NDVI ที่เสร็จแล้ว — 9 ตุลาคม 2569

ทดสอบ 60 จังหวัด–ปีเดิม (2014–2025) ครบทุกคู่ ค่า MAE/RMSE หน่วย **กก./ไร่ ยิ่งต่ำยิ่งดี**:

| คู่โมเดล | MAE ไม่มี NDVI | MAE เพิ่ม NDVI | RMSE ไม่มี → เพิ่ม NDVI | ปีที่ MAE ดีขึ้น / 12 |
| --- | ---: | ---: | ---: | ---: |
| Ridge ตามระยะผล | 189.6 | 198.1 | 243.7 → 250.9 | 3 |
| Ridge ทั้งปี | 191.8 | 195.5 | 247.0 → 249.8 | 5 |
| Random Forest ตามระยะผล | 210.0 | 206.8 | 268.8 → 266.8 | 7 |
| Gradient Boosting ตามระยะผล | 205.6 | 213.2 | 262.1 → 268.0 | 2 |

**ข้อสรุป:** รอบนี้ NDVI ยังไม่ทำให้แบบที่ดีที่สุดดีขึ้น คง Ridge ตามระยะผลที่ MAE 189.6 เป็น benchmark อ้างอิง ไม่ใช้ปี outer test เลือกโมเดลแล้วประกาศว่าเป็นผลยืนยันใหม่ แบบ RF เพิ่ม NDVI ลด MAE 3.26 กก./ไร่ หรือ 1.55% จากคู่ RF เดิม แต่ยังแย่กว่า Ridge เดิม ส่วน Ridge เพิ่ม NDVI แย่ลง 8.51 กก./ไร่ หรือ 4.49%

ช่วง bootstrap เชิงพรรณนาของ **MAE ลดลง**: Ridge ระยะผล −18.29 ถึง +0.22, Ridge ทั้งปี −10.81 ถึง +2.81, RF +0.45 ถึง +6.31, Gradient Boosting −16.15 ถึง −1.01 กก./ไร่ ใช้ resampling ทั้งปี ไม่ใช่ 60 แถวอิสระ แต่ไม่ได้แก้ serial dependence/การลองหลายแบบ จึงไม่ตีความเป็นหลักฐานนัยสำคัญหรือเหตุทางชีวภาพ

ผลรายจังหวัดของคู่ Ridge ตามระยะผล:

| จังหวัด | MAE ไม่มี NDVI | MAE เพิ่ม NDVI |
| --- | ---: | ---: |
| จันทบุรี | 201.1 | 211.3 |
| ศรีสะเกษ | 193.6 | 200.7 |
| อุตรดิตถ์ | 168.7 | 158.9 |
| สุราษฎร์ธานี | 212.1 | 237.3 |
| ชุมพร | 172.5 | 182.4 |

Ridge ดีขึ้นเฉพาะอุตรดิตถ์ในรอบนี้ ส่วน RF ดีขึ้น 4 จังหวัดแต่ชุมพรแย่ลง ไม่ควรเลือกใช้งานแยกจังหวัดจากคะแนน 12 ปีชุดนี้โดยไม่มีรอบยืนยันใหม่ ตัวแปร `ndvi_fruit_mean` ของ Ridge ที่เลือกมี missing 49 จาก 60 แถวทดสอบ และ `ndvi_pre_bloom_mean` มี missing 20 จาก 60 แถว สัญญาณช่วงผลจึงอ่อนและพึ่งค่าทดแทนมาก

ตรวจผลแล้ว: predictions 900 แถว = 15 วิธี × 60 จังหวัด–ปี ไม่มีคีย์ซ้ำ/ค่าทำนายไม่จำกัด; predictions ของคู่ไม่มี NDVI ทั้ง 10 แบบ (600 แถว) ตรงกับ benchmark เดิมทุกค่า ส่วน `inner_selected` เปลี่ยนเพราะมี candidates เพิ่ม ไม่ใช้เป็นคู่เพิ่ม NDVI เพียงตัวแปรเดียว ตรวจ hash ของข้อมูล/โค้ดทุกไฟล์ตรง manifest และทดสอบ Python ผ่าน 84 ข้อ รวม scale/QA, การไม่ใช้ target ทดสอบ, การเติมค่าจาก train เท่านั้น และ retry/cache เมื่อ API ตัดการเชื่อมต่อ

ดู [กราฟผลเทียบ](harvest_stage_rolling_ndvi_comparison.png), [ผลและวิธีทดลองทั้งหมด](harvest_stage_rolling_ndvi_results.json), [ค่าจริง–ค่าทำนาย](harvest_stage_rolling_ndvi_predictions.csv) รอบนี้ยังไม่เชื่อม NDVI/ภัยแล้งเข้าหน้าเว็บและไม่แทนที่โมเดลหลัก งานต่อที่มีเหตุผลคือกำหนดพื้นที่ให้ผลจริง/ตรวจแผนที่ land cover ให้ตรงก่อนทดลอง EVI หรือ NDMI พร้อมแยกทดสอบสัญญาณความเขียวจาก missing indicators และยืนยันกับข้อมูลปีใหม่ที่ยังไม่เคยดู

## ทดลอง VPD และตัดปีเก่าด้วยเกณฑ์ปฏิทิน — 9 ตุลาคม 2569

ตามคำขอให้เพิ่ม VPD ใช้ข้อมูลอากาศที่มีจริง `T2M_MIN`, `T2M_MAX`, `RH2M` คำนวณ **daily VPD proxy** หน่วย kPa โดยอิง [FAO-56 บท 3 สมการ 11/12/19](https://www.fao.org/4/X0490E/x0490e07.htm):

```
e(T) = 0.6108 × exp(17.27 × T / (T + 237.3))
es = (e(Tmin) + e(Tmax)) / 2
VPD_proxy = es × (1 − RH2M / 100)
```

NASA POWER `RH2M` เป็นความชื้นเฉลี่ยรายวัน ไม่ใช่ค่าเฉลี่ยระหว่าง RHmax/RHmin ตามนิยามสมการ 19 จึงเป็นการประยุกต์แบบประมาณ ไม่อ้างว่าเป็น VPD กลางวันรายชั่วโมงหรือ VPD ใบพืชจริง ค่า RH=100 ให้ VPD=0 ซึ่งเป็นค่าจริงตามสูตร ช่องว่าง/ค่าผิดช่วงไม่เติมศูนย์ และคำนวณ VPD รายวันก่อนรวมตามระยะ ไม่แทนด้วยสูตรบนอุณหภูมิเฉลี่ยรายปี

เพิ่มเฉพาะ 2 features ต่อคู่: แบบทั้งปีใช้ mean/p90 ของ daily proxy; แบบระยะผลใช้ mean ใน 90 วันก่อนดอกสมมติ และ p90 ใน 30 วันแรกหลังดอกสมมติ ถ่วงการปรากฏของวันตามทุกวันเก็บที่เป็นไปได้ในฤดูที่เรียนจาก train ค่า p90 นี้ไม่ใช่เกณฑ์ลูกร่วงทุเรียน และค่าเฉลี่ยรายวันอาจไม่จับเหตุร้อนจัดเพียงไม่กี่ชั่วโมง

ใช้ 74 configurations เช่น NDVI แต่แยกการทดลอง ไม่รวมสองตัวแปรกลุ่มนี้พร้อมกันในรอบนี้ ตรวจคู่ Ridge ทั้งปี/ตามระยะ, RF และ Gradient Boosting บน target เดิม ใช้ข้อมูลปีก่อนเท่านั้นในการจูน การเพิ่ม VPD เป็นการแปลงข้อมูล T/RH เดิม ไม่เพิ่มจำนวน target อิสระ

**ปีเก่า:** ผลผลิตต่อไร่หารด้วยเนื้อที่ให้ผล ไม่ใช่เนื้อที่ปลูกใหม่ จึงไม่ลบแถวเพราะยอดตันต่ำ ทดลอง sensitivity แยกโดยกำหนด cutoff **2010** ก่อนดูคะแนน ไม่กรองค่าผลผลิต แบบเดิมฝึกจาก 2004 ทดสอบ 2014–2025 (60 แถว); แบบช่วงใหม่ฝึกจาก 2010 ทดสอบ 2017–2025 (45 แถว) เพื่อมีอดีตพอสำหรับ inner validation 3 ปี ปฏิทินฤดูของแบบช่วงใหม่เรียนจากข้อมูล 2010 เป็นต้นไปด้วย ก่อนเทียบสองช่วงต้องจำกัดผลทดสอบให้เป็น 2017–2025 เหมือนกัน จำนวนตัวอย่างช่วงใหม่มีเพียง 80 จังหวัด–ปีและอาจเพิ่มความผันผวน อายุสวน/พันธุ์/การจัดการยังไม่ถูกควบคุมครบ

```powershell

& .\.build\national-analysis-venv\Scripts\python.exe -X utf8 tools\compare_harvest_stage_yield.py --vpd --train-start-year 2010
```

## รวมอากาศตามระยะผล VPD และ NDVI พร้อมจูนโมเดลเพิ่ม

ตามคำขอเพิ่มเติม ทดลองบนข้อมูลฝึก 2010–2025 และ outer test 2017–2025 เดิม โดยไม่ตัดจังหวัด–ปีที่ NDVI ขาด เพิ่มทั้งชุด NDVI, VPD และ NDVI + VPD ให้คู่ Ridge ทั้งปี/ตามระยะ, RF และ Gradient Boosting พร้อมจูนโมเดลที่ใช้ features ระยะผลรวมทุกกลุ่มอีก 3 แบบ:

- CatBoost 1.2.10: Ordered boosting, 400 iterations, depth 2/4, L2 3/20, learning rate 0.03/0.1 รวม 8 parameter sets × 4 อายุ = 32 configs ใช้ CPU thread เดียวและ seed 42 ไม่สร้าง `catboost_info` ไม่ early-stop ด้วย outer test
- Extra Trees: 150 trees, depth 3/5, min leaf 3/8, max features 0.7/1.0 รวม 8 sets × 4 อายุ = 32 configs
- RBF SVR: C 0.1/1/10, gamma scale/0.03/0.3, epsilon 0.1 บน target ที่ standardize รวม 9 sets × 4 อายุ = 36 configs ทั้ง scaler X และ y fit เฉพาะ train ของแต่ละ fold แล้วแปลงค่าทำนายกลับเป็น กก./ไร่

กำหนด grid ก่อนดูผลรอบนี้ รวม **236 configs** = 43 เดิม + 31 NDVI + 31 VPD + 31 รวมสองกลุ่ม + 100 advanced ค่า parameter และอายุเลือกจาก MAE เฉลี่ย 3 validation years ก่อนปี outer test เท่านั้น จากนั้น refit อดีตทั้งหมด ไม่สุ่มแถวข้ามปี ไม่ใช้ outer test เป็น eval_set ส่วนการเพิ่มการทดลองหลังเห็นผลรอบก่อนยังเป็น exploratory search ไม่ใช่ holdout ยืนยันใหม่ [CatBoost parameter tuning](https://catboost.ai/docs/en/concepts/parameter-tuning) และ [Ordered boosting parameters](https://catboost.ai/docs/en/references/training-parameters/common) เป็นแหล่งวิธี ไม่ใช่หลักประกันว่าจะชนะ Ridge

"รวม" ในรอบนี้หมายถึง **features ที่จับคู่จริงครบตาม province–year**: จังหวัด/ปี, ผลผลิตต่อไร่ปีก่อน, อากาศตามระยะ, VPD และ NDVI พร้อม missing indicators ไม่ใส่ pH/NPK ที่สมมติ ไม่เอาฝนแทนน้ำท่วมจริง และไม่ใส่ช่องว่างทะเบียนภัยเป็นศูนย์ ดิน/ภัยพิบัติเก็บแยกไว้รอพื้นที่–ปีและคุณภาพ coverage ที่ตรวจครบ เป็นงานต่อ ไม่ได้อ้างว่าโมเดลนี้รวมข้อมูลสวนรายต้นทุกอย่างแล้ว

```powershell
& .\.build\national-analysis-venv\Scripts\python.exe -X utf8 tools\compare_harvest_stage_yield.py --ndvi --vpd --advanced --train-start-year 2010
```

ผลใหม่เขียน `harvest_stage_rolling_combined_advanced_recent2010_results.json`, `_predictions.csv`, `_comparison.png` แยกจาก NDVI/VPD รอบก่อน `inner_selected` เลือกจาก pool ที่ขยายจึงต้องรายงานคะแนนจริงแยก ไม่เลือกเพียงโมเดลที่ได้ outer MAE ต่ำสุดแล้วประกาศว่าระบบเลือกถูกทุกปี

### ผลรอบรวมและจูนขั้นสูงที่เสร็จแล้ว

ทุกแถวด้านล่างใช้ 45 จังหวัด–ปีทดสอบ 2017–2025 และอดีตตั้งแต่ 2010 เหมือนกัน หน่วย กก./ไร่:

| วิธี | MAE | RMSE |
| --- | ---: | ---: |
| Ridge ตามระยะผล | 194.9 | 250.3 |
| Ridge + NDVI | 205.9 | 258.4 |
| Ridge + VPD | 190.9 | 243.4 |
| Ridge + VPD + NDVI | 191.7 | 235.1 |
| CatBoost รวม features | 205.6 | 269.4 |
| Extra Trees รวม features | 212.7 | 270.7 |
| SVR รวม features | 227.2 | 286.8 |
| ระบบเลือกจาก inner validation (236 configs) | 205.5 | 261.5 |

**ข้อค้นพบ:** การรวม VPD + NDVI ลด RMSE ประมาณ 3.4% จาก Ridge + VPD แต่ MAE เพิ่ม 0.79 กก./ไร่ (0.41%) ไม่มีวิธีใดดีที่สุดทั้งสอง metric และโมเดล nonlinear ที่จูนเพิ่มยังไม่ชนะ Ridge ในข้อมูลชุดนี้ ระบบเลือกแบบจากอดีตได้ MAE 205.5 แม้การจัดอันดับย้อนหลังจะมี Ridge + VPD ที่ 190.9 จึงไม่อ้างว่าระบบจะเลือกแบบดีที่สุดได้ล่วงหน้า

คู่ Ridge รวม VPD + NDVI เทียบ VPD อย่างเดียว MAE ดีขึ้น 5/9 ปี ช่วง bootstrap เชิงพรรณนาของ MAE ลดลง −30.39 ถึง +32.10 กก./ไร่ กว้างและคร่อมศูนย์ ส่วนการรวมเทียบ NDVI อย่างเดียวลด MAE 14.29 กก./ไร่ ไม่ใช่การพิสูจน์ผลทางชีววิทยาของ VPD ตารางต่อไปแสดงทั้งจังหวัดที่ดีขึ้นและแย่ลง:
