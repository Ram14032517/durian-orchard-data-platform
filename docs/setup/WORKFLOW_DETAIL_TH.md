## โค้ดโมเดลผลผลิตทีละขั้นใน VS Code

สำหรับงาน Ridge + VPD ที่เลือกจากการทดลองปีหลัง เริ่มที่ [tools/durian_model/README_TH.md](../../tools/durian_model/README_TH.md) มีไฟล์ขั้น 0-6, Notebook ที่ execute แล้ว และรายงานผล รันผ่าน Terminal หรือเมนู Terminal > Run Task > `Durian ML` ได้ ใช้ข้อมูลใน repo ไม่ต้องใช้ API key

อัปเดต 8 ตุลาคม 2569 · ใช้ repo หลักนี้เท่านั้น

เปิดโฟลเดอร์โปรเจกต์ใน VS Code แล้วเปิดไฟล์นี้ กด **Ctrl+Shift+V** เพื่ออ่านแบบมีลิงก์ ไม่ต้องเปิดทุกไฟล์หรือเลือก HTML ใน `tools/`

หน้าแผนที่ล่าสุด: แผนที่อยู่ซ้าย ตัวเลือกและข้อมูลอยู่ขวา (จอแคบเรียงลงด้านล่าง) เลือกจังหวัด–อำเภอ–หน่วยดิน **A และ B แยกกัน** โดยกด “เพิ่มพื้นที่ B” เมื่อต้องการเปรียบเทียบ → กด “ตกลง / ดูข้อมูล” เพื่อย่อฟอร์มเหลือแถบชื่อ A/B → เลือกวันที่และกดดูอากาศ เปิดฟอร์มใหม่ด้วย “แก้ไขพื้นที่” หรือย่อเองได้ ระบบไม่ย่อเมื่อเปลี่ยนแท็บและไม่ขยายเมื่อคลิกแผนที่ พิกัดอยู่ในฟอร์ม คุณสมบัติดินอยู่ในแท็บ “ข้อมูลดิน” ปุ่มซูม A/B กำหนดว่าปุ่มจังหวัดและการคลิกแผนที่ใช้กับฝั่งไหน เปิดผ่าน `00_OPEN_REPORT.cmd` เพื่อใช้ API; เซิร์ฟเวอร์ไฟล์ธรรมดาไม่รองรับ API นี้

ในแท็บ “ข้อมูลดิน” มีปุ่ม “เลือกดิน A / เลือกดิน B” เพื่อเปิดตัวเลือกฝั่งนั้นโดยตรง ส่วน “ค่ารายวัน” เลือกแสดง **7 วัน / 10 วัน / ทั้งหมด** และกดหัวคอลัมน์เพื่อเรียงได้ ใช้หน้าก่อน/หน้าถัดไปดูวันอื่น การแบ่งหน้าไม่ลดจำนวนวันในกราฟหรือ CSV

หน้าตาใช้ Lumen Elements 4.0.0 สำหรับแท็บ ตัวเลือกเป้าหมาย A/B และคำแนะนำ ร่วมกับ Tailwind เดิมและธีมใน `web/assets/css/orchard_monthly_report.css` (โหลดหลัง Tailwind เพื่อคุมสีและรูปแบบ): แก้ CSS เดิมแล้วรัน builder แผนที่ตาม [คู่มือโค้ด](../../tools/README_TH.md#ปรับหน้าตาด้วย-tailwind) หากแก้ `web/assets/css/orchard_tailwind.css` ให้รัน `./tools/build_orchard_tailwind.ps1` ก่อน builder คนเปิดรายงานไม่ต้องติดตั้ง Node หรือ Tailwind ภาพทุเรียนเป็น SVG ใน template ไม่ใช่ภาพสวนจริง สี A เขียวเส้นทึบและ B ส้มเส้นประใช้ตรงกันทั้งแผนที่และกราฟ

ไฟล์ Lumen ที่ build แล้วอยู่ข้าง HTML: `orchard_lumen.js` และ `orchard_lumen.css` ห้ามแยก HTML ไปเปิดเดี่ยว ๆ หากแก้ `web/assets/js/orchard_lumen.js` ให้ติดตั้งแพ็กเกจ build ด้วย `pnpm --dir .build/lumen add --save-exact @santi020k/lumen-elements@4.0.0 esbuild@0.25.12` แล้วรัน `node tools/build_orchard_lumen.mjs` ใช้ semantic tokens ใน CSS ไม่แก้ไฟล์ vendor ที่สร้างแล้ว

## ลำดับทำงาน

แท็บใหม่ **จังหวัดและสวนวันนี้** รวมประมาณการผลผลิตจังหวัดจาก Ridge + VPD กับ snapshot เซนเซอร์สวนและฟอร์มระยะ/ให้น้ำ/สถานการณ์ที่สังเกต จังหวัดตาม A แต่จังหวัดสวนเลือกแยกและไม่ย้ายตาม A/B ตัวเลขจังหวัดปี 2569 ใช้อากาศที่เกิดแล้วหลังจบหน้าต่างฤดู ไม่ใช่พยากรณ์ก่อนเก็บเกี่ยว ปีที่ยังขาดอากาศอนาคตหรือผลผลิตปีก่อนแสดงเหตุผลแทนการเติมข้อมูล ค่าเซนเซอร์ตรวจ snapshot ทุก 5 นาทีและเตือนเมื่อเก่า แต่ยังไม่ได้ต่อ Google Sheets แบบต่อเนื่อง สถานะที่บันทึกอยู่เฉพาะเบราว์เซอร์ ไม่ใช่ข้อมูลสำรวจอัตโนมัติหรือข้อมูลที่ส่งเข้าเทรน

1. **ดูภาพรวม:** Terminal → Run Task → **Durian: 01 เปิดแผนที่ (เริ่มตรงนี้)** หรือดับเบิลคลิก [00_OPEN_REPORT.cmd](../../00_OPEN_REPORT.cmd) ตัวเปิดเริ่มเซิร์ฟเวอร์ในเครื่องและเปิดแผนที่ เลือกพื้นที่ A/B เดือน และกราฟจากหน้ารวม ไม่ต้องเลือก kernel
2. **อ่านเดือนที่สนใจ:** ใช้ **Durian: 02 อ่านรายงานรายเดือน** เลือกจังหวัด ปี ค.ศ. และเดือน รายงานพร้อมที่มาแสดงใน Terminal หรืออ่านจากแผนที่
3. **ดูโค้ดและหลักฐาน:** เปิด [00_OPEN_ME.ipynb](../../00_OPEN_ME.ipynb) เลือก kernel `.build/national-analysis-venv/Scripts/python.exe` แล้ว Run All เมื่อต้องการรันใหม่ อ่านข้อจำกัดประกอบ ผลที่บันทึกไว้กับผลรันใหม่อาจต่างกัน
4. **ตรวจชุดข้อมูลก่อนเทรน:** อ่าน [คู่มือ training](../../research_data/five_province_history/training/README_TH.md) และ [manifest](../../research_data/five_province_history/training/manifest.json) ดูคอลัมน์ หน่วย ค่าขาด ปีที่ครอบคลุม และ train/validation/test ข้อมูลภูมิภาคกับเซนเซอร์สวนเป็นคนละชุด
5. **ตรวจโค้ด:** ใช้ **Durian: 04 ทดสอบ Python** ก่อนแก้/รันโมเดล หากมี Node.js ใช้ `node --test tests/*.js` ตรวจ JavaScript รวมถึง A/B ตารางรายวันและการส่งออกด้วย
6. **ทดลองโมเดล:** ใช้ **Durian: 05 รันโมเดล baseline (เขียนผลทดลองใหม่)** งานนี้เขียนผลใน training ไม่จำเป็นต้องรันเพื่อดูรายงาน เปรียบเทียบ MAE กับ baseline บนช่วงทดสอบที่ไม่เคยใช้ฝึกหรือเลือกโมเดล
7. **ส่งข้อมูลให้เพื่อน:** ใช้ **Durian: 03 เตรียม ZIP ข้อมูลเทรน (รักษา snapshot เดิม)** แล้วดาวน์โหลดจากแผนที่ หรือใช้ CSV โดยตรง ZIP เดิมไม่ถูกเขียนทับ จึงอาจไม่รวมผลทดลองที่เพิ่งรันใหม่ ต้องตรวจเทียบกับ CSV/manifest ปัจจุบันก่อนส่ง ไม่รวมข้อมูลสวนส่วนตัวที่ถูก ignore

เลขในเมนู task ช่วยหางาน ไม่ได้บังคับให้แพค ZIP ก่อนทดสอบหรือเทรน ถ้า Python ใช้ไม่ได้ ดู [README → Start here](../../README.md#start-here) สร้าง environment บนเครื่องตนเอง ไม่คัดลอก `.venv` ของเครื่องอื่น หาก VS Code จำ kernel เก่าต้องเลือกใหม่หนึ่งครั้ง

## ข้อควรแยกให้ชัด

- แก้หน้าแผนที่ที่ `web/templates/` และ `web/assets/` แล้วใช้ builder ตามคู่มือ อย่าแก้เฉพาะ HTML ที่สร้างแล้ว เพราะ build ถัดไปอาจเขียนทับ
- ข้อมูลสวน: สำรอง → ตรวจเวลา/หน่วย/ค่าขาด/อากาศค้าง → อ่านสำเนาคลีน → features → แบ่งตามเวลา → baseline ไม่ลบ raw และไม่แทนค่าขาดด้วยศูนย์
- ใช้ outdoor temperature/humidity ไม่ใช้ค่าเกตเวย์ในบ้านแทน NASA POWER เป็นข้อมูลกริด ไม่ใช่เซนเซอร์สวน
- โมเดลผลผลิตจังหวัดไม่ใช่โมเดลสุขภาพหรือความพร้อมออกดอกของต้น และยังไม่ยืนยันสาเหตุผลร่วง ต้องมีข้อมูลระยะพืช/ให้น้ำ/ผลผลิตจริงเพิ่ม
- `.build`, `.venv`, `.secrets` และ cache ซ่อนใน Explorer เพื่อลดความรก ไม่ได้ลบไฟล์และไม่ได้ล้าง secrets ในประวัติ Git

ทำต่อครั้งหน้าให้อ่าน [สถานะและงานที่ยังขาด](../operations/FIVE_PROVINCE_HANDOFF_TH.md) ก่อน เลือกทำทีละเรื่อง ไม่ต้องรันทุกสคริปต์หรือดาวน์โหลดข้อมูลใหม่ทุกครั้ง

## เว็บส่วนตัวบน Render และข้อมูลสด Supabase

เว็บที่ deploy: https://durian-orchard-dashboard.onrender.com — ใช้หน้า `/login` ชื่อผู้ใช้ `owner` และรหัสเดิมจาก `DASHBOARD_PASSWORD` ไม่ใช้กล่อง Basic Auth ของ browser แล้ว Session หมดอายุใน 8 ชั่วโมง มีปุ่มออกจากระบบในหัวเว็บ การเปลี่ยนรหัสฝั่ง Render จะทำให้ session เดิมใช้ไม่ได้ คีย์ Supabase ไม่อยู่ใน cookie หรือหน้าเข้าสู่ระบบ

เตรียม cloud server แล้วที่ `tools/serve_orchard_cloud.py` ใช้ Docker และ `render.yaml` แผน **free** เท่านั้น ยังไม่ใช่การยืนยันว่า deploy ขึ้นบัญชีแล้ว ทุกหน้า ไฟล์ข้อมูล และ API ต้องใช้รหัสผ่าน ยกเว้น `/healthz` สำหรับตรวจบริการ เหมาะกับเจ้าของสวนและผู้ร่วมดู 1–2 คน ใช้บัญชีร่วม ไม่ใช่ระบบสิทธิ์หลายผู้ใช้

1. รัน `python tools/build_unified_orchard_map.py` แล้ว `python tools/prepare_cloud_deploy.py` ด้วย Python ของโครงการ จะได้ `.build/deploy/durian-render.zip` ซึ่งมีเฉพาะไฟล์สำหรับบริการ ไม่รวมคีย์ อุปกรณ์ ข้อมูลเซนเซอร์ดิบ หรือไฟล์ส่วนตัว
2. เชื่อมบัญชี Render กับ repository ที่มีไฟล์ในชุด deploy และสร้าง Blueprint จาก `render.yaml` ไม่อัปโหลด ZIP ตรงเข้า Render และไม่ push งานค้างทั้ง workspace หากใช้ repo ใหม่ให้แตก ZIP แล้วอัปโหลดเฉพาะชุดนี้
3. ใน Environment ของ Render ตั้ง `SUPABASE_URL`, `SUPABASE_SECRET_KEY` และ `ORCHARD_DEVICE_ID` ให้ตรงระบบเดิม รหัส `DASHBOARD_PASSWORD` ถูก generate โดย Render อ่านจาก Environment เพื่อเข้าสู่เว็บด้วยชื่อ `owner` ห้ามใส่คีย์ Supabase ใน HTML, Git หรือแชท ไม่เปิด RLS ให้ทุกคนอ่านข้อมูลสวน
4. `ORCHARD_LOCATION_ID` ใช้เมื่อโมเดลสวนที่เลือกต้องอ่านพยากรณ์ ปัจจุบันเป็น persistence จึงยังไม่ใช้ ตัวอ่าน Supabase เป็น GET เท่านั้น ไม่มีแก้ schema/ข้อมูลหรือสั่งปั๊มน้ำ

หน้า “จังหวัดและสวนวันนี้” อ่าน Supabase ทุก 5 นาทีเมื่อเปิดดู แสดงเวลาข้อมูลและป้ายข้อมูลเก่าเมื่อเซนเซอร์หยุดส่ง โมเดลสวนปัจจุบันเป็น **baseline คงค่าความชื้น** สำหรับค่าเฉลี่ยชั่วโมงเป้าหมายอีก 6 ชั่วโมง ไม่อ้างว่าชนะ validation หรือทำนายผลผลิตสวน ส่วน Ridge + VPD เดิมคำนวณผลผลิตต่อไร่ระดับจังหวัด เมื่อช่วงอากาศครบเท่านั้น ไม่เติมอากาศอนาคต ถ้าฤดูผ่านไปแล้วให้ตีความเป็นการประมาณย้อนหลัง ไม่ใช่พยากรณ์ก่อนเก็บเกี่ยว

Render free มี cold start และพื้นที่ไฟล์ไม่ถาวร cache/ไฟล์ส่งออกอาจหายหลัง restart ข้อมูลถาวรอยู่ Supabase บันทึกระยะพืช/การให้น้ำที่กดในหน้าเว็บยังอยู่ localStorage ของ browser ไม่ใช่ฐานข้อมูลร่วม ต้องตรวจการเชื่อมต่อ Supabase จริงและ build Docker บน Render ก่อนถือว่าพร้อมใช้งานภายนอก
