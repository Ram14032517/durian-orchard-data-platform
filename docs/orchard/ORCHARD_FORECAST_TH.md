# พยากรณ์อากาศสวนและคำแนะนำเฝ้าระวัง

อัปเดต 28 ตุลาคม 2569 · หน้า “สวนของฉัน” เท่านั้น · Public HOLD คงเดิม

## การเชื่อมข้อมูล

- `web/react/src/OrchardForecast.jsx` ใช้การ์ด กราฟ และระบบบัญชีเดิม ผ่าน `/api/orchard-forecast`
- `tools/orchard_forecast.py` เรียก Open-Meteo Forecast API ทางเซิร์ฟเวอร์ ไม่สร้าง backend อีกตัว ไม่เปลี่ยนโมเดล ML
- ตำแหน่งคือสวนเซนเซอร์ที่เจ้าของส่งยืนยันในการสนทนานี้ เก็บเฉพาะ `.secrets/orchard_forecast_location.json` ซึ่ง Git และ Docker ไม่รวม ไม่เพิ่มใน DATA, HTML, GAP หรือ URL ของเบราว์เซอร์
- พิกัดส่งให้ Open-Meteo เพื่อขอพยากรณ์ตามคำสั่งเจ้าของ ตรวจ CRS WGS84 และขอบเขตประเทศไทย ตรวจบัญชีตรงกับเจ้าของและ device ที่ตั้งไว้ก่อนเรียก ไม่รับพิกัด บัญชี หรือ device จาก query string
- ใช้ได้เฉพาะบัญชีเจ้าของสวนเซนเซอร์นี้ ไม่ใช่บริการเลือกสวน GAP ใดก็ได้ บัญชีอื่นได้รับ 403 พิกัดไม่ได้ถูกบันทึกลง Supabase ในงานนี้
- บน cloud ต้องตั้ง `ORCHARD_FORECAST_LOCATION_JSON` เป็น secret รูปแบบเดียวกับไฟล์ local โดยผู้ดูแล ไม่คัดลอกไฟล์ส่วนตัวเข้า Docker และไม่เปิดสิทธิ์ข้อมูลเพิ่ม
- Free API ใช้เพื่อการศึกษาและไม่ใช่เชิงพาณิชย์เท่านั้น หากเปลี่ยนรูปแบบใช้งานต้องตรวจสิทธิ์ก่อน ระบบแสดงเครดิต Open-Meteo และ CC BY 4.0

## เวลา หน่วย และค่าขาด

ตั้ง `timezone=Asia/Bangkok`, `forecast_days=7`, อุณหภูมิ °C, ฝน mm, ลม km/h, VPD kPa ไม่มี API key ใหม่

รายชั่วโมง: temperature_2m, relative_humidity_2m, precipitation, precipitation_probability, wind_speed_10m, vapour_pressure_deficit

รายวัน: temperature_2m_min/max, precipitation_sum, precipitation_probability_max, wind_speed_10m_max; RH และ VPD รายวันเป็นค่าเฉลี่ยที่คำนวณจากพยากรณ์ 24 ชั่วโมง ต้องมีครบ 24 ค่า ไม่เติมช่องว่าง

- รายวันรวมวันนี้ทั้งวัน ไม่ใช่ยอดฝนที่วัดจริงแล้ว ไม่ใช่ 7 วันเต็มนับจากขณะนี้
- กราฟ 24/48 ชั่วโมงเริ่มเวลารายงานของชั่วโมงถัดไป ฝนและโอกาสฝนเป็นช่วงหนึ่งชั่วโมงก่อนเวลารายงานนั้น สรุปฝน 24/48/72 ชั่วโมงแสดงขอบเขตจริงของช่วงสะสม เริ่มจากต้นชั่วโมงปัจจุบัน จึงมีส่วนของชั่วโมงที่เริ่มไปแล้ว ไม่ใช่ยอดวัดจริง
- ไม่เปิดเผยพิกัด grid ที่ API ส่งกลับ และไม่ตีความเลขทศนิยมของพิกัดว่าเป็นความละเอียดแบบจำลอง
- Best match ใช้แบบจำลองกริดโลกหลายชุดในประเทศไทย ความละเอียดต่างกันตามตัวแปร ไม่อ้างว่าระบุสวนได้ละเอียดจริง โอกาสฝนมาจาก ensemble ประมาณ 27 กม. ตามเอกสารผู้ให้บริการ
- `retrieved_at` คือเวลาที่เรียกข้อมูล ไม่ใช่เวลารันแบบจำลอง `model_issued_at=null` เพราะคำตอบ API ไม่ให้ metadata นี้ `generationtime_ms` ไม่ถูกใช้เป็นเวลาออกรายงาน
- ตรวจจำนวนเวลา ความต่อเนื่อง timezone และหน่วยทุกช่อง กำหนดค่าขาด/นอกขอบเขตโครงสร้างเป็น null พร้อม quality_flags ศูนย์จริงเก็บเป็นศูนย์ กราฟไม่ลากเส้นข้ามช่องว่าง

## แคชและสิทธิ์

แคชอยู่ในหน่วยความจำของเซิร์ฟเวอร์ 15 นาที ไม่เขียนพิกัดหรือ forecast ลงไฟล์สาธารณะ หน้าอ่านทุก 5 นาทีเมื่อเปิดอยู่ หากบริการล้มเหลวพักการลอง 5 นาที ไม่มี retry loop

ใช้สำเนาเก่าไม่เกิน 3 ชั่วโมงได้พร้อมคำเตือนและงดคำแนะนำจาก forecast เก่า เก่ากว่านั้นแสดง Error/Retry ไม่มีข้อมูลสมมติหรือจังหวัดสำรอง HTTP response เป็น private/no-store ไม่เปิด anonymous endpoint และไม่คืนพิกัด

## หลักคำแนะนำและข้อจำกัด

1. ฝนคาดการณ์มากกว่าศูนย์ในช่วงที่มีข้อมูลครบเป็นเพียงตัวช่วยจัดคิวตรวจทางน้ำและต้น ไม่ใช่เกณฑ์เกิดโรค ไม่ใช้ RH/VPD สร้างระดับความเสี่ยงโรคที่ยังไม่ผ่านการประเมิน
2. เซนเซอร์ใช้ประกอบได้ต่อเมื่ออุปกรณ์ผูกกับสวนนี้และผ่านสถานะระบบพร้อมค่าที่มีจริง ค่าศูนย์ที่ธง invalid ไม่ถูกใช้ตัดสินใจ ไม่มีคำสั่งปริมาณน้ำ ปุ๋ย หรือสารเคมี
3. ระยะที่บันทึกต้องอยู่ในสวนและบัญชีเดียวกัน และไม่เกิน 30 วันเพื่อเตือนให้ทบทวนบันทึก นี่เป็นอายุข้อมูลสำหรับ UI ไม่ใช่ช่วงชีววิทยาหรือเกณฑ์โรค ระยะที่ไม่พร้อมไม่เดาจากเดือน
4. บันทึกระยะเดิมเป็น localStorage ในเบราว์เซอร์ ในงานนี้แยกกุญแจตามบัญชีและสวนเซนเซอร์ ไม่ยกบันทึกเดิมที่ไม่มีเจ้าของมาใช้ และแจ้งว่าไม่ sync เข้า Supabase; ประวัติผลผลิตจริงยังใช้ Supabase เดิม
5. “โรคที่ตรวจพบจริง” แสดงยังไม่มีผลวินิจฉัย ไม่แปลงสภาพอากาศ รายงานจังหวัด หรือสิ่งที่ผู้ใช้สังเกตเป็นผลยืนยันโรค

### แหล่งอ้างอิงที่ตรวจ

- [Open-Meteo Forecast API](https://open-meteo.com/en/docs): ตัวแปร เวลา หน่วย การเลือกแบบจำลองและ ensemble
- [Terms & Privacy](https://open-meteo.com/en/terms): Free API เฉพาะ non-commercial; จำกัดต่ำกว่า 10,000 ครั้ง/วัน, 5,000/ชั่วโมง, 600/นาที ณ วันที่ตรวจ ไม่ใช่การรับรองว่าจะใช้เชิงธุรกิจได้
- [NABC สถานการณ์ศัตรูพืช](https://nabc.go.th/dashboard/agri-disaster/pests): หน้าเว็บที่อ่านระบุใช้ในรายงาน 28 ต.ค. 2569; นี่คือวันที่ที่ตรวจพบในหน้า ไม่ได้รับรองว่าทุกรายการเป็นเหตุการณ์วันนั้น
- [NABC API Service](https://agriapi.nabc.go.th/home) และ [Catalog](https://nabc.go.th/catalog): พบหน้าให้บริการ แต่ยังยืนยัน endpoint พร้อมข้ออนุญาตสำหรับโรคทุเรียนชุดนี้ไม่ได้ ไม่เรียก undocumented API ไม่ scrape ข้อมูลโรคอัตโนมัติ
- [กรมวิชาการเกษตร ฐานข้อมูลหมอนทอง](https://www.doa.go.th/hort/?page_id=53926): เนื้อหาที่ระบบค้นหาทางการทำดัชนีระบุการระบายน้ำไม่ดี น้ำขัง ความชื้นสะสม ฝน และการแพร่ของเชื้อรากเน่าโคนเน่า
- [กรมวิชาการเกษตร โรคผลเน่า](https://www.doa.go.th/leka/?p=3799): เนื้อหาที่ทำดัชนีระบุการตรวจผลช่วงใกล้เก็บเกี่ยวและหลีกเลี่ยงผลสัมผัสดิน/เกิดบาดแผล

การเปิดหน้า DOA โดยตรงในรอบนี้ timeout/502 จึงใช้เฉพาะคำแนะนำเชิงสำรวจทั่วไปที่ตรวจข้อความทำดัชนีของเอกสารทางการได้ ไม่อ้างว่าอ่านคู่มือเต็มหรือรับรองเกณฑ์ตัวเลขเฉพาะสวน ลิงก์ต้นทางอาจไม่พร้อมชั่วคราว

## อากาศปัจจุบัน (29 ต.ค. 2569)

เพิ่ม current conditions จาก Open-Meteo ในคำขอเดิม แยกจากเซนเซอร์จริงและพยากรณ์รายชั่วโมง ใช้ temperature_2m, relative_humidity_2m, precipitation, wind_speed_10m และ vapour_pressure_deficit แสดงเวลาที่ค่ามีผล เวลาที่ดึง อายุ และ interval ตาม API โดยตรง ฝน current ไม่ใช่ฝนต่อชั่วโมงหาก interval=900 วินาที (15 นาที) ไม่ใช้ hourly forecast แทนค่าปัจจุบัน หาก current ไม่พร้อมยังดูพยากรณ์เดิมได้ อายุเกิน 60 นาทีแสดงเก่า (เกณฑ์ความสดของหน้าจอ ไม่ใช่เกณฑ์โรค) ไม่ใช้ API current เป็นค่าตรวจวัดจริงหรือป้อนแทนเซนเซอร์/โมเดล ML
