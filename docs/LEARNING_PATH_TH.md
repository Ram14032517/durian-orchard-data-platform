## 1. เริ่มใน VS Code โดยไม่ต้องล็อกอิน

เปิดโฟลเดอร์ `C:\project` ซึ่งเป็นโปรเจกต์นี้อยู่แล้ว ปุ่ม Sign In ไม่จำเป็นสำหรับการฝึกในเครื่อง

ถ้าเห็น Restricted Mode: กด Manage บนแถบด้านบน เปิดหน้าจัดการ Workspace Trust แล้วเชื่อถือเฉพาะโฟลเดอร์ `C:\project` เมื่อคุณยืนยันว่าเป็นงานของคุณ การเชื่อถือโฟลเดอร์อนุญาตให้ VS Code รันโค้ดและส่วนขยายในโฟลเดอร์ได้ ไม่ใช่การล็อกอิน GitHub

เปิดไฟล์คู่มือนี้จาก Explorer > docs > LEARNING_PATH_TH.md กด Ctrl+Shift+V เพื่อดู Markdown แบบอ่านง่าย

เปิด Terminal > New Terminal แล้วรัน:

```powershell
Get-Location
& 'C:\Users\support\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' --version
```

ตำแหน่งควรเป็น `C:\project` ตรวจพบว่า `.venv` เดิมชี้ไป Python ของผู้ใช้ Admin ที่ไม่มีในเครื่องนี้ จึงยังใช้ไม่ได้ คำสั่งนี้ใช้ Python ที่มากับเครื่องมือในเครื่องเพื่อฝึกก่อน เส้นทางนี้เฉพาะเครื่องนี้และอาจเปลี่ยนเมื่ออัปเดต ภายหลังค่อยตั้ง environment ของโปรเจกต์ด้วย Python หรือ Anaconda ที่คุณติดตั้ง

หากใช้ส่วนขยาย Python ของ Microsoft ให้เปิด Command Palette ด้วย Ctrl+Shift+P เลือก Python: Select Interpreter แล้วเลือก Enter interpreter path และใช้เส้นทาง Python จากคำสั่งด้านบน ส่วน Jupyter ของ Microsoft ใช้เมื่อเริ่ม Notebook ภายหลัง

## 3. บทฝึกแรก: อ่านข้อมูลจริง

เปิด `learning/01_inspect_soil.py` อ่านทีละส่วน แล้วรันจาก Terminal:

```powershell
& 'C:\Users\support\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' learning/01_inspect_soil.py
```

โปรแกรมอ่าน CSV สำรองและพิมพ์ผล ไม่เขียนทับข้อมูล ลองตอบคำถามก่อนแก้โค้ด:

1. ข้อมูลมีจำนวนแถวและคอลัมน์เท่าไร? จำนวนแถวคือจำนวนต้นไม้หรือจำนวนครั้งที่วัด?
2. `df` คืออะไร? `df.head()` กับ `df.shape` ต่างกันอย่างไร?
3. ทำไมค่าที่อ่านไม่ได้จึงใช้ NaN แทน 0?
4. ข้อมูลอยู่ในช่วงเวลาใด? ทำไมต้องแปลง UTC เป็นเวลาไทยก่อนแบ่งเช้า/กลางวัน?
5. มี event_id ซ้ำหรือไม่? ไฟล์นี้ผ่านการ export/เตรียมข้อมูลมาแล้ว จึงอาจไม่พบปัญหาที่เคยมีในต้นฉบับ

ทดลองเปลี่ยน `EXAMPLE_THRESHOLD` จาก 30 เป็น 25 และ 35 แล้วเทียบจำนวนจุดที่ต่ำกว่าเกณฑ์ ตัวเลขนี้เป็นแบบฝึกเขียนเงื่อนไข ยังไม่ใช่เกณฑ์แนะนำสำหรับทุเรียน

## 5. ออกแบบงานดินแห้งให้ตรวจสอบได้

เริ่มจากแสดงค่าความชื้นที่วัดได้ พร้อมธงคุณภาพข้อมูล แล้วค่อยทดลองเงื่อนไขต่ำกว่าเกณฑ์ แยกตามอุปกรณ์และช่วงเวลา เกณฑ์จริงต้องอาศัยการสอบเทียบเซนเซอร์ ชนิดดิน ตำแหน่ง/ความลึก และข้อมูลภาคสนาม

ผลหนึ่งเหตุการณ์ควรมี device_id, เวลาเริ่ม, เวลาสิ้นสุด, ค่าต่ำสุด, ระยะเวลาที่สังเกตได้, เกณฑ์ที่ใช้ และสถานะคุณภาพข้อมูล อย่านับช่วงข้อมูลหายว่าแห้งต่อเนื่องหรือเอาจำนวนแถวคูณ 15 นาทีโดยไม่ตรวจช่วงห่างจริง

ค่าซ้ำอาจเกิดตามธรรมชาติ จึงใช้คำว่า “สงสัยค่าค้าง” เมื่ออาศัยการซ้ำอย่างเดียว ถ้ามีเวลาที่เซนเซอร์อัปเดตล่าสุดหรือสถานะ Gateway ให้ใช้เป็นหลักฐานร่วมด้วย

แยก `unknown` เมื่อข้อมูลไม่พอออกจาก `normal` และเก็บแถวต้นฉบับไว้ การเติมค่าหายต้องระบุวิธีและจำกัดช่วงที่เติม ไม่เติมผ่านช่วงอุปกรณ์ดับยาวโดยอัตโนมัติ

แยก “ช่วงของวัน” เช่น เช้า/กลางวัน/เย็น ออกจาก “ระยะการเติบโต” เช่น แตกใบ/ออกดอก/เลี้ยงผล ระยะการเติบโตต้องมีบันทึกจากสวนก่อนจึงนำมาแบ่งวิเคราะห์ได้

## 6. ก่อนเรียกว่าโมเดลเรียนรู้สุขภาพพืช

กฎ `ค่าความชื้น < เกณฑ์` เป็น rule-based baseline การให้โมเดลเรียนรู้ผลจากกฎเดียวกันยังไม่ได้พิสูจน์ว่าตรวจสุขภาพต้นได้ ต้องมีบันทึกอาการจริง เวลาให้น้ำ ต้นที่ตรวจ และระยะการเติบโตสำหรับประเมิน

เมื่อเริ่ม ML ให้ใช้ข้อมูลเก่าฝึกและข้อมูลใหม่ทดสอบ คำนวณค่าที่เรียนรู้ เช่น scaler หรือเกณฑ์จาก quantile ด้วยชุด train เท่านั้น และสร้างฟีเจอร์จากข้อมูลที่มี ณ เวลาทำนาย หลีกเลี่ยงนำข้อมูลอนาคตมาใช้
