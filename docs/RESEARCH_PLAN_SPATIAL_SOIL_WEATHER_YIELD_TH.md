# แผนวิเคราะห์เชิงพื้นที่: ดิน–อากาศ–ผลผลิตทุเรียน

บันทึกแผนงาน ณ 8 ตุลาคม 2569 สำหรับทำต่อใน repo หลัก `durian-orchard-data-platform` เอกสารนี้แยกข้อมูลที่มีอยู่จากงานที่ยังต้องตรวจหรือรวบรวม ตัวเลขและสมมติฐานในส่วน “แผน” ยังไม่ใช่ผลการวิจัย

## เป้าหมาย

ศึกษาว่าอากาศและองค์ประกอบของชุดดินสัมพันธ์กับผลผลิตทุเรียนต่อพื้นที่อย่างไรใน 5 จังหวัด ได้แก่ จันทบุรี ชุมพร ศรีสะเกษ อุตรดิตถ์ และสุราษฎร์ธานี โดยเชื่อมผลผลิต อากาศ และ GIS ที่ระดับพื้นที่และปีเดียวกันเท่าที่ข้อมูลจริงรองรับ

หน่วยวิเคราะห์ที่ต้องการคือ **อำเภอ–ปี** หากได้ผลผลิตและพื้นที่เก็บเกี่ยวรายอำเภอที่ตรวจย้อนกลับได้ หากข้อมูลที่ยืนยันได้มีเพียงระดับจังหวัด ให้ใช้ **จังหวัด–ปี** และสรุปเป็นการสำรวจความสัมพันธ์ระดับจังหวัดเท่านั้น

## สถานะข้อมูลที่มีใน repo

- `research_data/five_province_history/training/annual_yield_windows_panel.csv` มี 145 แถวครบ (5 จังหวัด × 29 ปี) ตั้งแต่ ค.ศ. 1997–2025 เป็นผลผลิตต่อไร่ระดับจังหวัดและสรุปอากาศ 6 เดือนก่อนเดือนอ้างอิง อากาศมาจากจุดอ้างอิง NASA POWER ไม่ใช่ค่ารายแปลงหรือรายชุดดิน
- `research_data/five_province_history/training/README_TH.md` บันทึกนิยาม target, การแบ่ง train/validation/test และผลทดลอง baseline ข้อมูลนี้รวมทุเรียนทุกพันธุ์ ไม่ได้ใช้ยืนยันสาเหตุหรือทำนายผลผลิตรายสวน
- มีขอบเขตชุดดิน LDD ปีผลิต 2561 ใน 5 จังหวัด สำหรับแสดงแผนที่ ส่วนการซ้อนทับ land-use รหัส A403 ที่ผ่านการประมวลผลมี 4 จังหวัดและคนละปี: จันทบุรี 2568, ชุมพร 2564, ศรีสะเกษ 2565, อุตรดิตถ์ 2563; สุราษฎร์ธานียังไม่มีชั้น land-use นี้ซ้อนกับชุดดินในงานดังกล่าว ดู `research_data/regional_orchards/SOURCE_TH.md` และ `research_data/priority_provinces/soil_layers/SOURCE_TH.md`
- ยังไม่มีผลผลิตจริงรายอำเภอ–ปีที่ตรวจแหล่งต้นทางครบทั้ง 5 จังหวัด และยังไม่มีชุดข้อมูลผลผลิตจริงแยกตามชุดดิน
- ตัวเลขสัดส่วนดินรายอำเภอ ตัวคูณ S1/S2/S3 และสาเหตุภัยพิบัติที่อยู่ในข้อความ/ตารางร่าง ยังไม่ถือว่าเป็นข้อมูลยืนยันจนกว่าจะตรวจไฟล์ต้นทางและคำนวณซ้ำ

## วิธีวิเคราะห์ที่กำหนด

1. **Target:** ผลผลิตต่อไร่จริง = ผลผลิตจริง ÷ เนื้อที่เก็บเกี่ยวจริงของพื้นที่และปีเดียวกัน ใช้ระดับอำเภอเมื่อเอกสารต้นทางรองรับ หากมีเพียงผลผลิตจังหวัดให้ใช้ target ระดับจังหวัด
2. **ดิน:** ซ้อนแผนที่การใช้ที่ดินทุเรียนกับชุดดินและขอบเขตอำเภอ เพื่อคำนวณพื้นที่ทุเรียนและสัดส่วนพื้นที่บนแต่ละหน่วยดิน ใช้สัดส่วนและคุณสมบัติดินเป็นตัวแปรอธิบาย ไม่กระจายผลผลิตไปสร้าง label รายชุดดิน
3. **อากาศ:** ดึงข้อมูลรายวัน/รายชั่วโมงจากแหล่งเดียวกันในช่วงและพิกัดที่สอดคล้องกัน แล้วสรุปตามช่วงฤดูที่มีหลักฐานแยกตามภูมิภาค ตัวแปรที่พิจารณา ได้แก่ อุณหภูมิสูง/จำนวนวันร้อน ฝนสะสมและช่วงฝนทิ้ง แสง ความชื้น/VPD และลมกระโชก
4. **ปฏิสัมพันธ์:** ทดลองอย่างจำกัด เช่น ฝนหนัก × สัดส่วนพื้นที่ลาดชัน หรือความร้อน/ฝนทิ้งช่วง × สัดส่วนดินที่มีคุณสมบัติอุ้มน้ำต่างกัน โดยรายงานเป็นความสัมพันธ์ ไม่เรียกผลเชิงสาเหตุหากการออกแบบและข้อมูลยังไม่รองรับ
5. **การประเมิน:** เทียบกับ baseline ง่าย ๆ และแบ่ง train/validation/test ตามปี ห้ามสุ่มแถวข้ามปี เลือกโมเดลจาก validation และเก็บ test สำหรับประเมินครั้งสุดท้าย

ไม่ใช้ตัวคูณผลผลิตที่สมมติขึ้นตามชั้นความเหมาะสมดิน เช่น S1 = 1.1–1.2 หรือ S3 = 0.7–0.8 เว้นแต่พบหลักฐานเชิงประจักษ์และวิธีสอบเทียบที่ตรวจสอบได้ และไม่ถือว่าเปอร์เซ็นต์ชุดดินที่คำนวณจากพื้นที่ปลูกเป็นผลผลิตจริงของดินนั้น

## งานที่จะทำต่อ เรียงตามลำดับ

### 1. ตรวจหลักฐานผลผลิตรายอำเภอ

- รวบรวมรายงาน PDF/Excel จากสำนักงานเกษตรจังหวัด/อำเภอ และระบบหรือเอกสารทางการที่เกี่ยวข้อง แยกจังหวัด อำเภอ ปี และแหล่งที่มา
- บันทึกค่าผลผลิต พื้นที่เก็บเกี่ยว พันธุ์ (ถ้ามี) หน่วย นิยาม และสถานะหลักฐานเป็น `candidate` หรือ `verified`
- ตรวจความสอดคล้องของยอดอำเภอรวมกับยอดจังหวัด และบันทึกปีที่ไม่มีข้อมูล ห้ามเติม missing เป็นศูนย์
- หากหาได้ไม่ครบ ให้ระบุช่วงปีและอำเภอที่ใช้ได้จริง แล้วตัดสินใจว่าจะทำ district-year panel หรือใช้ province-year panel ต่อ

**ผลส่งมอบ:** ตาราง evidence พร้อมลิงก์/ชื่อเอกสารและหมายเหตุการตรวจสอบ

### 2. ตรวจชั้นข้อมูลดินและพื้นที่ปลูก

- ยืนยันแหล่ง ไฟล์ ปีผลิต/ปีสำรวจ รหัสพืช ความละเอียด และสิทธิ์การใช้ของแผนที่แต่ละชุด รอบตรวจเดิมยืนยันคำอธิบาย A403 ว่าเป็นทุเรียนใน 4 จังหวัดที่มีข้อมูล แต่ปีแผนที่และการจำแนกพื้นที่ปลูกผสมยังต้องระบุแยก
- แยก A403 ตรงตัวออกจากชั้น/รหัสพื้นที่ปลูกผสมตาม attribute จริง ห้ามนับพื้นที่ปลูกผสมทั้งหมดเป็นแปลงทุเรียนโดยไม่มีหลักฐาน
- หา land-use สำหรับสุราษฎร์ธานีและตรวจความครอบคลุมทั้ง 5 จังหวัด ถ้าไม่มีชั้นทุเรียนเฉพาะ ให้บันทึกช่องว่างและไม่สร้างพื้นที่ทุเรียนขึ้นเอง
- คำนวณ intersection ด้วย CRS แบบฉายที่เหมาะกับพื้นที่ ตรวจพื้นที่รวม พื้นที่ไม่ทับซ้อน geometry และสัดส่วนที่เหลือ/ไม่ทราบชนิดพืช
- ระบุว่า soil share เป็น static หรือ semi-dynamic ตามปีแผนที่ ไม่ใช้เหมือนเป็นข้อมูลรายปี
- ตรวจเงื่อนไขใบอนุญาตก่อนเผยแพร่ไฟล์ดินหรือผล overlay ที่แจกจ่ายต่อได้

**ผลส่งมอบ:** ตารางพื้นที่ปลูกทุเรียนตามอำเภอ–ชุดดิน–ปีของแผนที่ พร้อม coverage และ provenance

### 3. ทำอากาศให้ตรงพื้นที่และช่วงฤดู

- ใช้ NASA POWER ที่มีอยู่เป็น baseline และประเมิน ERA5-Land/Open-Meteo เป็นแหล่งเสริมด้วยพิกัด/ช่วงเวลาตรงกันก่อนเลือกแหล่งหลัก ไม่เปลี่ยนไปใช้ Windy Point Forecast เป็นข้อมูลย้อนหลัง
- หากใช้ข้อมูลกริด ให้บันทึกพิกัด cell ต้นทาง ความละเอียด เวลา หน่วย รุ่นข้อมูล และวิธีถ่วงพื้นที่
- กำหนดช่วงฟื้นต้น ทำใบ ออกดอก ติดผล และเก็บเกี่ยวแยกจังหวัด/ภูมิภาคจากหลักฐานอ้างอิง ระบุว่าเป็นปฏิทินอ้างอิงหากไม่มีวันที่จริงรายสวน
- ตัวแปรอย่าง Tmax > 38°C, CDD/SPEI และเกณฑ์ฝนหนักให้เป็น candidate features จนกว่าจะมีแหล่งวิชาการ/เกณฑ์ที่เหมาะกับทุเรียนและพื้นที่รองรับ
- เก็บ gust จากแหล่งที่มีตัวแปรลมกระโชกจริง ไม่ใช้ลมเฉลี่ยแทนพายุ

**ผลส่งมอบ:** อากาศรายพื้นที่–วัน พร้อมตารางสรุปตามฤดูและที่มาของทุกตัวแปร

### 4. สร้าง panel และ baseline

หนึ่งแถวต่อพื้นที่–ปี (หรือพื้นที่–ปี–ช่วงฤดู เมื่อ target รองรับ) โดยมีอย่างน้อย:

| หมวด | ตัวอย่างคอลัมน์ |
| --- | --- |
| พื้นที่/เวลา | `province_code`, `district_code`, `year_ce`, `stage`, `soil_map_year`, `landuse_year` |
| Target จริง | `production_tonnes`, `harvested_area_rai`, `yield_kg_rai` |
| องค์ประกอบดิน | `durian_area_rai`, `soil_share_*`, `soil_coverage_pct` |
| อากาศ | `stage_tmax_days`, `stage_rain_mm`, `stage_cdd`, `stage_solar`, `stage_vpd`, `stage_max_gust` |
| หลักฐาน | `yield_source`, `weather_source`, `soil_source`, `evidence_status`, `quality_note` |

ใช้ข้อมูล `verified` สำหรับ fit โมเดล ส่วน candidate ใช้ตรวจต่อและแสดงสถานะเท่านั้น หากมีเพียง 5 จังหวัด ให้เริ่มจากสถิติเชิงพรรณนาและโมเดลเชิงเส้นอย่างระมัดระวัง ไม่เพิ่มตัวแปรจำนวนมากจนเกินจำนวนข้อมูล

### 5. ประเมินและสื่อสารผล

- เทียบ baseline กับโมเดลที่เพิ่มอากาศ/สัดส่วนดิน โดยใช้ข้อมูลปีเดียวกันและรายงาน MAE/RMSE พร้อมจำนวนตัวอย่างและช่วงทดสอบ
- ทำ sensitivity check แยกช่วงปีและแหล่งอากาศเมื่อทำได้
- แสดงบนแผนที่ว่าชั้นใดเป็นข้อมูลจริง จุดกริด หรือค่าประมาณ พร้อมปีแผนที่และ coverage
- เขียนข้อสรุปว่าอะไรสัมพันธ์กับผลผลิตและความไม่แน่นอนอะไรยังเหลือ หลีกเลี่ยงถ้อยคำว่าอากาศหรือชุดดิน “ทำให้” ผลผลิตลด หากยังไม่มีการออกแบบเชิงสาเหตุ
- ไม่แปลงผลโมเดลระดับจังหวัด/อำเภอเป็นคำแนะนำให้น้ำรายสวนหรือสุขภาพต้น

## ผลทดลองที่ทำแล้วและขั้นตอนถัดไป (8 ตุลาคม 2569)

ทดสอบแนวคิด “งวดการผลิตย้อนจากเดือนเก็บเกี่ยว” กับผลผลิตจริงต่อไร่แล้ว ใช้ nested rolling ตามเวลา 12 รอบ (2014–2025), 60 จังหวัด–ปี เปรียบเทียบ Ridge, Random Forest, Gradient Boosting และฐานประวัติผลผลิต เลือกฤดูและจูนจากอดีตในแต่ละ fold เท่านั้น ดูผล/แหล่งวิธีวิจัย/คำสั่งรันใน [คู่มือ training](../research_data/five_province_history/training/README_TH.md#ทดลองหลายปีแบบ-nested-rolling-8-ตุลาคม-2569)

Ridge เพิ่มอากาศระยะผลให้ MAE 189.6 กก./ไร่ เทียบคู่ไม่มีอากาศ 198.2 แต่ดีขึ้นเพียง 6 จาก 12 ปี และแย่ลงในอุตรดิตถ์/สุราษฎร์ธานี ส่วนโมเดลต้นไม้เพิ่มอากาศไม่ชนะคู่ไม่มีอากาศ ขณะนี้จึงได้ pipeline ทดสอบสมมติฐานที่รันซ้ำได้ **ยังไม่ได้พิสูจน์สาเหตุของผลผลิตหรือความสมบูรณ์ต้น** และยังไม่มีผู้ชนะที่ยืนยันด้วยข้อมูลใหม่

ลำดับงานที่เหมาะกับหลักฐานนี้:

1. ทำ weather exposure ให้แทนพื้นที่ให้ผลจริง: ขอเนื้อที่ให้ผลรายอำเภอ/กริดและปีให้ตรงจังหวัด ถ้ามีกริดกึ่งแปลง ใช้ `ค่าอากาศจังหวัด–วัน = Σ(ค่าอากาศกริด × พื้นที่ให้ผลในกริดของปีนั้น) / Σพื้นที่ให้ผลที่ครอบคลุม` บันทึกส่วนพื้นที่ที่หายไปด้วย ไม่ใช้พื้นที่ปลูกใหม่หรือ soil polygon ทั้งจังหวัดเป็นน้ำหนักแทน ไม่ถือว่าค่าเฉลี่ยเหนือพื้นที่ปลูกทั้งหมดคือค่าเฉลี่ยเหนือพื้นที่ให้ผล
2. ทดลองการถ่วงวัน/เดือนเก็บเกี่ยวด้วยสัดส่วนจาก **อดีตของ fold ฝึก** แทนการให้น้ำหนักทุกวันเท่ากัน พร้อมเปรียบเทียบชุดตัวแปรอากาศชนิดเดียวกันระหว่างหน้าต่างทั้งปีและระยะผล เพื่อแยกประโยชน์จากการจัดเวลา ผลนี้จะเป็นสมมติฐานรอบใหม่ ไม่เลือกวิธีตามปีทดสอบเดิมแล้วเรียกว่าเป็นผลยืนยัน
3. เชื่อมดินเป็นคุณสมบัติพื้นที่: ระบุปีแผนที่/สัดส่วนดิน และแยกค่าตามเอกสารชุดดินจากค่าตรวจสวนจริง ค่า pH/NPK ที่ไม่มีหลักฐานยังเป็น missing ไม่เติมจากความเหมาะสมปลูก และไม่สร้างผลผลิตรายชุดดินจากยอดจังหวัด ดินคงที่กับตัวแปรจังหวัดอาจซ้อนกันจนแยกผลไม่ได้
4. เก็บวันดอกบาน พันธุ์ อายุ/จำนวนต้นให้ผล ผลร่วง ให้น้ำ และผลผลิตรายสวน เพื่อสอบเทียบช่วงระยะพืชและสมมติฐานความต้องการน้ำ/การสร้างอาหาร ไม่ใช้ฝนหรือรังสีแสงเพียงอย่างเดียวเป็นผลวัดสรีรวิทยา
5. แยกงานพยากรณ์ใช้งานจริงจากงานย้อนหลัง: เก็บ `issued_at` ต้นทาง, lead time, ข้อมูลที่รู้ได้ถึงวันออกคำทำนาย และ forecast ทุกฉบับไม่เขียนทับ จึงค่อยทดสอบความเสี่ยงล่วงหน้าและเทียบกับเหตุ/ความเสียหายที่สำรวจจริง

### หลักฐานภัยพิบัติที่รวบรวมแล้ว 8 ตุลาคม 2569

เพิ่มการค้น **ปภ. เฉพาะ 5 จังหวัด** ผ่านสถิติหมู่บ้านและระบบข่าว: กรองสถิติน้ำท่วม/วาตภัยได้ 8,363 แถวต้นทาง และข่าวที่ค้นได้ช่วง 2020–2025 จำนวน 143 รายการ ตรวจวัน/อำเภอแล้ว 7 รายงาน พร้อมตารางเทียบวันเกิดเหตุกับเดือนเก็บเกี่ยวจริง 237 แถวตามอายุสมมติ 120–150 วัน ดู [รายละเอียดและแหล่งทั้งหมด](../research_data/five_province_history/PHENOLOGY_SOURCES_TH.md#รายงาน-ปภ-เจาะ-5-จังหวัด-ตรวจ-8-ตุลาคม-2569) และรัน `tools/prepare_ddpm_disasters.py` เพื่อทำซ้ำ

ข้อมูลยังแยกจาก ML training: ช่องว่างไม่เป็นศูนย์ ปี 2567 สถิติกลางยังไม่ยืนยันว่าครบปี กันรหัสหมู่บ้านวาตภัยจันทบุรีที่ขัดกัน 2 แถวออก และข่าวศรีสะเกษในระบบนี้ขาดช่วงหลังปี 2022 จึงไม่สร้างตัวแปร "ไม่มีภัย" จากปีที่หาไม่พบ ต้องติดตามประกาศ/รายงาน ปภ. จังหวัดและตรวจการทับ **พื้นที่ให้ผลจริง** ก่อนนับ exposure

ขั้นต่อไปของสมมติฐานเหตุระยะสั้น: สรุป Tmax สูงสุด/วันร้อนต่อเนื่อง และฝนสูงสุดสะสม 3/7 วันตามระยะผล เปรียบเทียบกับ baseline ด้วย chronological validation เช่นเดิม แยก "เหตุร้อน/ฝนจากอากาศ" ออกจาก "เหตุภัย/ผลร่วงที่หน่วยงานสำรวจ" ไม่แปลงปริมาณฝนเป็นน้ำท่วมจริงหรือแปลงพื้นที่ได้รับผลกระทบเป็นตันที่เสียหาย

ใช้ panel จังหวัด–ปีที่มีอยู่ 1997–2025 เพื่อวิเคราะห์ความสัมพันธ์เบื้องต้นระหว่างผลผลิตต่อไร่กับอากาศ และอาจเพิ่ม soil composition ระดับจังหวัดเป็นตัวแปรสำรวจได้ แต่การแยกผลของดินออกจากความแตกต่างประจำจังหวัดจะอ่อนมากเมื่อมีเพียง 5 จังหวัด จึงไม่ใช้สรุปว่า soil series ใดให้ผลผลิตสูงกว่า

## เพิ่มภัยแล้งและ NDVI — 9 ตุลาคม 2569

ดาวน์โหลดทะเบียนภัยแล้ง ปภ. `dpm-gd028` ปีชุดรายงาน 2562–2568 แล้ว คัด 5 จังหวัดได้ 2,655 ระเบียน เก็บใน `drought_area_records.csv` ต่างระดับพื้นที่/ต่างนิยามวันสิ้นสุดต้องแยกกัน และไม่ใช่ทุกระเบียนมีความเสียหายทุเรียน ดู [ข้อจำกัดและแหล่ง](../research_data/five_province_history/PHENOLOGY_SOURCES_TH.md#ภัยแล้งจาก-ปภ-เพิ่ม-9-ตุลาคม-2569)

ทดลองเพิ่ม NDVI จริงจาก NASA ORNL MOD13Q1 ใน benchmark เดิมด้วย `--ndvi` กำหนดก่อนดูผล: คู่ Ridge ทั้งปี, Ridge ตามระยะผล, Random Forest ตามระยะผล, Gradient Boosting ตามระยะผล เพิ่มเฉพาะ NDVI 2 ตัวต่อคู่และใช้ปีฝึก/ทดสอบเดียวกัน จูนอายุและ parameters จาก 3 ปี validation ก่อนปีทดสอบ ค่าขาดเติม median ของ fold ฝึกพร้อม indicator ไม่เติมศูนย์ ไม่ปรับแบบตามคะแนน outer test แล้วเรียกว่าเป็นผลยืนยัน รายงานผลใน [training README](../research_data/five_province_history/training/README_TH.md)

NDVI รอบจุดเป็น **context patch ไม่ใช่พื้นที่ให้ผลเฉลี่ยจังหวัด** ยังต้องหาขอบเขต/น้ำหนักพื้นที่ให้ผลจริงรายปีเพื่อแยกสวนใหม่และพืชอื่น ทั้งภัยแล้งจากรายงานและ NDVI อาจเป็นตัวชี้วัดสำรวจ แต่ไม่เท่ากับวัดการสร้างอาหาร/ความสมบูรณ์ต้นหรือพิสูจน์เหตุของผลผลิต

ผลทดลอง NDVI เสร็จแล้ว: โหลด 2,645 งวด ผ่าน QA 1,017 งวด เทรน 15 วิธีบน 60 จังหวัด–ปีเดียวกัน Ridge ระยะผล MAE 189.6 → 198.1 เมื่อเพิ่ม NDVI (แย่ลง); RF 210.0 → 206.8 (ดีขึ้นเล็กน้อยแต่ยังแพ้ Ridge เดิม) ไม่เปลี่ยนโมเดลหลักจากผลนี้ ข้อมูลเป็น patch ผสมพืชและมีช่องว่างมาก ปีที่ annual NDVI ผ่าน temporal coverage มีเพียง 25/110 แถว ดูคะแนนครบทุกคู่/ทุกจังหวัดและกราฟใน training README ที่ลิงก์ด้านบน ขั้นต่อไปควรแก้ความตรงของพื้นที่และการครอบคลุมก่อนเพิ่มความซับซ้อนโมเดล

เพิ่ม VPD daily proxy ตาม FAO-56 โดยใช้ Tmin/Tmax/RH2M และเทรนคู่เดิมแล้ว: Ridge ตามระยะผล MAE 189.6 → 187.7 ในชุดยาว และ 194.9 → 190.9 เมื่อฝึกเฉพาะ 2010 เป็นต้นไป บนช่วงทดสอบเดียวกัน 2017–2025 แบบ VPD ที่ฝึกจาก 2004 ได้ 203.6 เทียบฝึกจาก 2010 ได้ 190.9 กก./ไร่ ผลเบื้องต้นสนับสนุนให้ศึกษาช่วงปีใหม่ แต่ยังไม่มั่นคงทุกจังหวัดและช่วง bootstrap ของประโยชน์ VPD คร่อมศูนย์ ตัดปีด้วยปฏิทิน ไม่ตัดเพราะผลผลิตต่ำ ใช้ผลผลิตต่อเนื้อที่ให้ผลเดิม ไม่มีการสร้าง target จำลอง ดูรายละเอียด/สูตร/ผลทุกคู่ใน training README

รอบรวม VPD + NDVI และจูน CatBoost/Extra Trees/SVR เสร็จแล้ว (236 configs, 26 วิธี, 45 จังหวัด–ปีเดียวกัน): Ridge รวมได้ MAE 191.7/RMSE 235.1 เทียบ VPD อย่างเดียว 190.9/243.4 จึงมีผลแลกเปลี่ยน ไม่ได้ชนะทุก metric CatBoost 205.6, Extra Trees 212.7, SVR 227.2 MAE กก./ไร่ ยังไม่ชนะ Ridge ทุกผล/parameters/folds เก็บแยกใน `harvest_stage_rolling_combined_advanced_recent2010_*` ดิน/ภัยที่ยังจับคู่พื้นที่–ปีไม่ครบยังไม่ใส่เป็น feature และไม่แปลงช่องว่างเป็นไม่มีภัย ทดสอบ Python ล่าสุด 89 ข้อผ่าน
