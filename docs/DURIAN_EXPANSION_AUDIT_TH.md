## 1. ข้อมูลจริงที่มี

ห้าจังหวัดเดิมคือ จันทบุรี (22), ศรีสะเกษ (33), อุตรดิตถ์ (53), สุราษฎร์ธานี (84), ชุมพร (86)
สองจังหวัดอยู่ภาคใต้ จึงไม่ใช่ตัวแทนครบทุกภาคของประเทศไทย

ไฟล์ต้นทาง OAE รายปีมี 4,428 แถวตัวชี้วัด / 1,107 จังหวัด–ปี / 67 จังหวัด
ครอบคลุม 1997–2025 แต่ไม่ได้ครบทุกจังหวัดทุกปี ตารางที่เตรียมไว้เทียบค่าทั้งสี่ตัวชี้วัดกับ XLSX ต้นทางแล้วตรงกัน
มี 30 จังหวัดที่มีเป้าหมายใช้ได้ครบ 2010–2025 ตามเกณฑ์ผลผลิตไม่ติดลบและพื้นที่ให้ผลมากกว่าศูนย์
ตัวเลขนี้เป็นความครบถ้วนเชิงตาราง ไม่ใช่การยืนยันคุณภาพการสำรวจหรือความพร้อมใช้งานย้อนหลัง
ข้อมูลไม่แยกพันธุ์: เป้าหมายยังเป็นทุเรียนทุกพันธุ์ ไม่ใช่ผลผลิตหมอนทองล้วน

ทั้งห้าจังหวัดมีรายปีครบ 1997–2025 และรายเดือน 2004–2016 จำนวน 13 ปีต่อจังหวัดที่ยอดรวมตรงรายปีภายใน tolerance สูงสุดระหว่าง 1 ตันกับ 0.5%
เดือนที่ไม่มีแถวไม่ถูกเติมเป็นศูนย์ การเทียบยอดรวมนี้ไม่พิสูจน์ว่าเดือนที่ขาดเป็นศูนย์จริง

โค้ด `load_panel()` จำกัดจังหวัดห้ารหัสและจำนวน 80 แถวไว้ตายตัว จึงนำ CSV จังหวัดใหม่มาแทนตรง ๆ ไม่ได้
โค้ดเตรียมข้อมูลอากาศก็ใช้รายการห้ารหัสตายตัว โมเดลที่ serialize แล้วตรวจ schema ห้าจังหวัดด้วย
ควรสร้าง loader/manifest สำหรับงานทดลองขยายแยกจาก loader Production ไม่แก้สัญญา API เดิม

## 5. A/B/C/D แบบเปลี่ยนทีละปัจจัย

| ชุด | จังหวัดฝึก | ปีเริ่มฝึก | เปรียบเทียบเพื่อแยกผล |
|---|---|---:|---|
| A | 5 เดิม | 2010 | จุดอ้างอิงหลังซ่อม availability ให้ผ่าน |
| B | 5 เดิม + 6 ผู้สมัคร | 2010 | B–A ผลการเพิ่มจังหวัดอย่างเดียว |
| C | 5 เดิม | 2004 | C–A ผลการเพิ่มประวัติอย่างเดียว |
| D | 5 เดิม + 6 ผู้สมัคร | 2004 | D–C ผลจังหวัดบนประวัติยาว และ D–B ผลประวัติบนจังหวัดขยาย |

ไม่ใช้ D–A เป็นข้อสรุปเหตุเดียวเพราะเปลี่ยนสองปัจจัย
ทุกชุดรายงานผล five-original แยกบน 45 keys เดิม: 2017–2025 × 5 จังหวัด
จังหวัดใหม่รายงานแยกบน keys เดียวกันระหว่าง B/D ไม่เฉลี่ยรวมแล้วประกาศชนะระบบเดิม
รายงานจำนวน keys ที่ผ่าน availability และถูกตัดพร้อมเหตุผล ถ้าไม่ครบห้ามเทียบ MAE กับ 204.85 เหมือนเป็นชุดเดียวกัน
ค่าของ A ที่ผ่าน availability อาจต่างจาก 204.85 จึงต้องใช้ A เป็นคู่เทียบหลักใหม่

### กติกาการฝึก

- Expanding walk-forward outer test 2017–2025; ทุก fold ฝึกได้เฉพาะปีก่อนหน้าและ label ที่ประกาศแล้ว
- Inner folds สามปีสุดท้ายก่อน outer test เพื่อรักษาชุดเปรียบเทียบเดิม ทุกขั้น season fitting, preprocessing และ normal fitting ทำภายใน fold
- ตรึง CatBoost depth {2,3}, learning_rate 0.03, l2_leaf_reg 10, iterations 400 และ seed 42 เพื่อไม่เพิ่มงบ tuning ไปพร้อมการเพิ่มจังหวัด
- เลือก depth จาก inner errors บนห้าจังหวัดเดิมเท่านั้นในทุกแขน เพื่อให้เกณฑ์เลือกตรงกันและไม่เปลี่ยน objective เมื่อเพิ่มจังหวัด
- เก็บเสริม inner metrics จังหวัดใหม่ แต่ไม่ใช้เป็น criterion สลับโมเดลระหว่าง A/B/C/D
- สำหรับแขนปี 2004 inner ช่วงต้นยังมีประวัติ season ไม่พอ ห้ามใช้เดือนในอนาคต ต้อง skip fold ด้วยเหตุผลหรือมี season prior ที่เผยแพร่แล้ว
- split รายปีทั้งจังหวัดไปด้วยกัน ไม่ random split และไม่เลือกโมเดลจาก 2017–2025
- outer ช่วงนี้เคยตรวจแล้ว: เป็นงานทดลอง exploratory ไม่ใช่ independent holdout ใหม่ การเลือกผู้ชนะหลังอ่านคะแนนยังมี selection optimism

### Feature ablation

แต่ละแขนทดสอบ CatBoost ชุดเต็มกับ CatBoost province + year + lag เท่านั้น ใช้ split และงบ depth เดียวกัน
ห้ามเอา CatBoost ชุดเต็มไปเทียบ Ridge lag-only แล้วตีความว่าความต่างทั้งหมดเกิดจากอากาศ
จำแนก full-feature weather เป็น observed-as-of + climatology ส่วนที่ยังไม่ทราบจริง
ผลดีขึ้นจึงบอกประโยชน์ของ feature bundle ใน scenario นี้ ไม่ใช่ความแม่นของ weather forecast ที่ยังไม่มี
ตั้ง bootstrap รายปีเก็บห้าจังหวัดเป็น block ร่วมกัน และรายงานช่วงประมาณการแบบ descriptive เนื่องจาก test ถูกเห็นมาแล้ว

## 7. Reanalysis / Climatology / Historical Forecast

NASA POWER ในชุดนี้เป็น historical gridded estimates ไม่ใช่ archived issued forecast
อากาศในอดีตอาจมีการประมวลผลหรือปรับปรุงภายหลัง วันที่ observation เก่าอย่างเดียวไม่พิสูจน์ availability
โค้ดสมมุติ lag เจ็ดวันยังไม่ได้สอบเทียบ release latency จริง
Climatology ใช้ค่าเฉลี่ย calendar day สิบปีก่อนแถวเป้าหมาย ไม่ใช่พยากรณ์เฉพาะปี
Historical Forecast ต้องเก็บ issue time, valid time, model version และเลือกเฉพาะรอบที่ออกก่อนวันพยากรณ์
ห้ามใช้ endpoint พยากรณ์ปัจจุบันเพื่ออ้างว่าเป็น forecast ที่ออกจริงเมื่อปี 2017
Observed future weather ใช้ได้เฉพาะ oracle benchmark แยก ไม่รวมคะแนน operational หรือเกณฑ์ขึ้น Production

เพิ่ม audit script และ unit tests แบบไม่แตะข้อมูลต้นทาง โมเดล API หรือหน้าเว็บ
เก็บ coverage ทั้ง 67 จังหวัด, paired errors ทั้ง 45 keys, ตารางรายจังหวัด/ปี และ JSON hashes/ข้อจำกัด
ตรวจ weather context 1,120 แถว: cutoff ไม่เกิน issue, normal_end_year ต่ำกว่าปีเป้าหมาย และ fractions รวมหนึ่ง
checks นี้ยืนยันตรรกะ cutoff ของ metadata ไม่พิสูจน์วันประกาศจริง

คำสั่งรันซ้ำจาก repository root:

```powershell
.build/national-analysis-venv/Scripts/python.exe -X utf8 tools/durian_model/audit_expansion.py
.build/national-analysis-venv/Scripts/python.exe -X utf8 -m unittest discover -s tests -p test_expansion_audit.py
```

ลำดับทำต่อ: รวบรวม OAE vintages และฤดูผลิตที่เผยแพร่แล้ว → เติม release manifest → ตรวจ gate →
ดึง daily weather จังหวัดผู้สมัครพร้อม provenance → รัน A/B/C/D และ within-arm weather ablation → ประเมินแยกกลุ่ม
Production ยังใช้เดิมจนกว่าจะมีหลักฐานการลด error หลายปี โดยไม่มีพื้นที่ใดเสียหายรุนแรงขึ้นและ availability ผ่าน
ยังไม่มีคะแนนชุดขยายหรือผล ablation ใหม่ในรายงานนี้ ไม่อ้างว่าเพิ่มจังหวัดทำให้แม่นขึ้น
