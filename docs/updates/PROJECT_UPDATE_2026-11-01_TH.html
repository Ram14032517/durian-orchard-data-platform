บันทึกแก้ปัญหาโปรเจกต์ — 1 พฤศจิกายน 2569

งานรอบนี้รวมตัวแก้ hash จากรอบก่อนและแก้ปัญหาที่ทำได้จากโค้ด/หลักฐานที่มี โดยไม่ train ใหม่ ไม่เปลี่ยนโมเดลผลผลิต/ความชื้น ไม่สร้างผลตรวจโรคหรือผลผลิตรายสวน และไม่เผยแพร่ข้อมูลส่วนบุคคลเพิ่ม ทำงานบน branch codex/organize-project ฐาน 5463ab1

สิ่งที่แก้แล้ว

1. Hash และความเข้ากันได้ข้าม Mac/Windows

คง SHA256 ของไบต์จริงไว้เสมอ แต่ให้ input CSV ของโมเดลหลักสามไฟล์พิสูจน์ความเท่ากันแบบ LF/CRLF ได้ ต้องคำนวณกลับมาได้ digest ที่บันทึกไว้จริง ไม่ trim ช่องว่าง ไม่ลบ BOM ไม่เรียงแถว และไม่ยอมรับค่าข้อมูลเปลี่ยน ตัวตรวจของ API, custom prediction ขั้น 6 และ availability/preparation ใช้หลักฐานเดียวกัน โดยยังแยก actual_sha256, expected_sha256, comparison ไว้

โมเดลหลัก ridge_vpd_final_model.json มีข้อยกเว้นเฉพาะ newline ในลักษณะเดียวกัน ไม่ขยายไปยอมรับ JSON/โค้ดทุกไฟล์ และยังเก็บ/check raw hash ก่อน–หลังงานทดลอง เพื่อไม่ให้เปลี่ยนโมเดลระหว่างรันผ่านได้ การยอมรับรูปแบบไฟล์ไม่เปลี่ยน publication date หรือทำให้ข้อมูลกลายเป็น point-in-time certified

เพิ่ม .gitattributes สำหรับข้อมูลและหลักฐานที่ต้องคงไบต์ ป้องกัน Git แปลง newline ซ้ำใน clone ใหม่ ดู บันทึกตัวแก้แรก สำหรับที่มา

2. คืนหลักฐาน NOAA ให้ตรง snapshot เดิม

พบประกาศ ENSO 9 ไฟล์ที่ checkout ไม่ตรง hash ใน documents.csv เดิม ดึงจาก URL ทางการ NOAA ที่บันทึกในแต่ละระเบียนลงที่ชั่วคราว และคืนไฟล์เฉพาะเมื่อ SHA256 ตรง digest เดิมทุกไบต์ ไม่มีการเปลี่ยน expected hash, สถานะ ENSO, วันที่ประกาศ หรือคะแนนโมเดล

รายละเอียด URL/hash ก่อน–หลังอยู่ใน RESTORATION_2026-11-01.json ตัวตรวจไฟล์ archive ยังคงแบบไบต์ตรง ไม่ใช้ข้อยกเว้น newline ของ input CSV กับหลักฐาน HTML/PDF

แก้ความต่างของ PDF text extractor ที่แบ่ง and เป็น an d: อนุญาตเฉพาะ whitespace ในข้อความ evidence ของ PDF โดยตัวอักษรอื่นทั้งหมดต้องตรง ไบต์ PDF, วันที่ และ state ยังตรวจตรงตามเดิม ไม่แก้ PDF/metadata และยังคงข้อจำกัด historical content authentication = unverified

3. Path ชั่วคราวบน macOS

แก้ guard ที่ปฏิเสธ /var/... เพราะ macOS resolve เป็น /private/var/... ยอมรับเฉพาะ alias ของโฟลเดอร์ชั่วคราวระบบตามจริง ไม่ยอมรับ symlink ที่ผู้ใช้สร้างเพิ่มเพื่อหนีออกจาก root ยังคงปฏิเสธ path traversal, output ซ้ำ และการเขียนทับ artifacts เดิม

4. เทสต์หลัง clone

แยก unit tests ของการขยายจังหวัด/target/การตรวจคุณภาพ ให้ใช้ข้อมูลสังเคราะห์ที่ติดป้ายชัด แทนการโหลด sealed snapshot จริงมาเป็น fixture ของ fake estimator แก้ import ของ fixture ให้รันได้ทั้ง unittest discover และเลือกโมดูลโดยตรง

เทสต์หลักฐานภายในที่ไฟล์ไม่ได้อยู่ใน Git แสดง skip พร้อมรายการที่ขาด ไม่ถูกนับว่าผ่าน และไม่มีการ upload raw/private evidence เพิ่ม มีโหมด ORCHARD_REQUIRE_RESEARCH_FIXTURES=1 ให้ตรวจแบบบังคับว่าต้องมีครบ ไฟล์ที่มีแต่ seal/hash ผิดยังต้อง fail ไม่ถูกจับแล้วข้าม อ่าน คู่มือทดสอบ

5. GAP บน local/cloud

/api/project ประกาศ capabilities ตามโหมด เซิร์ฟเวอร์ cloud แจ้งว่าไม่เปิดชั้นหมุด GAP และ frontend ไม่พยายามดาวน์โหลดไฟล์ที่ถูกบล็อกหรือชวน retry 404 ส่วน local ใช้ชุดหมุดเดิม 32,871 จุดได้ตามเดิม

ถ้าโหลดผิดพลาดจริง ข้อความแนะนำ file:// จะใช้เฉพาะเมื่อเปิดแบบ file ส่วน HTTP แนะนำตรวจ server/ชุดข้อมูล ไม่แสดงสาเหตุผิดประเภท ไม่ได้เปิด route GAP/Excel/private preparations บน cloud และไม่เปลี่ยน Docker allowlist เพื่อเผยแพร่พิกัดเพิ่ม

6. โหมด IoT ในเครื่องให้ชัด

ค่าเริ่มต้นยังเป็น ORCHARD_DATA_SOURCE=local_snapshot เพื่อรักษาพฤติกรรมเดิม เพิ่ม opt-in ORCHARD_DATA_SOURCE=supabase สำหรับคนที่ตั้งการเชื่อมต่อฝั่งเซิร์ฟเวอร์แล้ว หากเลือกโหมดสดแต่เชื่อมต่อไม่ได้จะไม่ fallback เป็น snapshot แล้วอ้างว่าข้อมูลสด

หน้าเว็บบอกแหล่งข้อมูลปัจจุบัน การตั้งค่าที่ไม่ครบอธิบายว่าเป็นของเครื่อง/เซิร์ฟเวอร์นี้ ไม่สรุปว่า cloud เดิมเสีย API identity ส่งเฉพาะ source/boolean ว่าตั้งค่าไว้หรือไม่ ไม่ส่ง key, URL Supabase, device ID หรือพิกัดสวน

สิ่งที่คงเดิม

หน้าแรกสวนของฉัน รหัสและขอบเขตอุปกรณ์ สัญญาอ่านข้อมูล IoT การยืนยันตัวตน cloud/CSRF/HTTPS/RLS และข้อจำกัดไฟล์ส่วนตัวไม่ถูกลดลง ข้อมูลผลผลิต/อากาศที่ใช้ฝึก audit เดิม โมเดล และ Excel GAP ไม่ถูกเขียนทับ หน้าแผนที่ build ใหม่ด้วย --reuse-bundled-data ซึ่งรักษา JSON DATA snapshot เดิม ไม่ดึงประวัติหรือสร้างโมเดลใหม่

การ push นี้ไม่ใช่คำสั่ง deploy หรือ merge เข้า main ถ้าแพลตฟอร์มตั้ง auto-deploy เองต้องตรวจสถานะของแพลตฟอร์มแยกต่างหาก

  • JavaScript: ผ่าน 57/57 ไม่มีข้าม รวมถึงการนำทางแผนที่ A/B, GAP, missing data, weather fallback/export และขอบเขต IoT
  • localhost จริง: /api/project ตอบ 200 พร้อม capabilities, ปี 2027 จังหวัด 84 ตอบ 200 pending_prior_yield โดยไม่สร้างตัวเลข/เรียกอากาศแทนผลผลิตปีก่อน, manifest GAP ตอบ 200 และหน้าเว็บแสดงหมุดจังหวัดสุราษฎร์ธานี 11,081 จุดเป็น 17 กลุ่ม ณ มุมมองที่ตรวจ ไม่มี console error ในการตรวจครั้งนี้
  • หน้าแรกยังเป็นสวนของฉัน ระบุโหมด snapshot และประวัติสวนแจ้ง 503 orchard_not_configured อย่างชัดเจนเพราะเครื่องนี้ยังไม่ตั้ง credentials ไม่อ้างว่าแก้การเชื่อมต่อจริงสำเร็จหรือ cloud ล่ม
  • ตรวจ input/artifacts/model ที่ป้องกันไว้ 27 ไฟล์ไม่เปลี่ยนไบต์, JSON DATA ในแผนที่ตรงกับ HEAD เดิม, SEASONS_MAP.html ไม่เปลี่ยน และ Excel GAP ยังคง SHA256 ef3d25feca214050e5e190d0f6d7f1fcc6e09e704d0bdb7b0205b8cb6c39af6c
  • การทดสอบอัตโนมัติบล็อก requests ออกเครือข่ายภายนอกและอนุญาต localhost สำหรับเทสต์ HTTP เท่านั้น การตรวจ UI ใช้หน้า localhost จริง ไม่มีการ train หรืออ้างผลความแม่นยำใหม่

สิ่งที่ยังต้องมีข้อมูลหรือสิทธิ์เพิ่มเติม

  • IoT จริงบน Mac ต้องตั้ง Supabase URL, server key และ ORCHARD_DEVICE_ID ฝั่งเครื่อง ไม่ใส่ค่าลับในเอกสาร/แชต/Git และไม่เดาค่าให้ เว็บ cloud จริงยังต้องมี URL/session เพื่อยืนยันเวลาวัดจากสวนแบบ end-to-end
  • ไฟล์วิจัย private/archived ที่ขาดยังไม่ถูกกู้หรือเผยแพร่ โค้ด/หลักฐานของ sealed runs เก่าที่ fingerprint ไม่ตรงต้องตรวจฉบับเดิมหรือสร้าง preparation ฉบับใหม่โดยมี provenance แยก ไม่ปลอม seal
  • GAP ยังเป็น registry/map/preparation ไม่ใช่ผล train ใหม่ การทดลองต้องตรวจพิกัดและ coverage ก่อนใช้แผนดึงอากาศแบบจำกัดจำนวน แล้วเทียบด้วยชุดประเมินเดียวกัน ยังไม่อ้างความแม่นเพิ่มกี่เปอร์เซ็นต์
  • เป้าหมายทำนายโรคยังต้องมีผลตรวจพบและไม่พบโรคที่มีวันที่ รหัสสวน/ต้น และผู้ยืนยัน ข้อมูล GAP ไม่สร้าง labels เหล่านี้ให้เอง ไม่มีการเพิ่ม LLM เพื่อเดา ground truth หรือข้อแนะนำรักษาโรคที่ยังไม่ได้ยืนยัน
