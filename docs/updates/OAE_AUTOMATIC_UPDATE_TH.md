# อัปเดตผลผลิตและพื้นที่ OAE อัตโนมัติ

หน้า `/yield` ขอ `/api/province-production` เมื่อเปิดครั้งแรก ไม่ต้องกรอกปีใหม่เอง เมื่อสลับไปหน้าอื่นและกลับมาจะคงข้อมูลใน React เดิม การตรวจจริงฝั่งเซิร์ฟเวอร์จำกัดวันละครั้งต่อแคช ถ้าผิดพลาดพักหนึ่งชั่วโมง ไม่มีการยิงซ้ำไม่จำกัด ไม่ใช่งานตั้งเวลาที่รันแม้ไม่มีผู้เปิดเว็บ

ใช้ CKAN metadata `https://catalog.oae.go.th/api/3/action/package_show?id=durian_product` เลือกไฟล์ระดับจังหวัดเพียงหนึ่งรายการ อ่านชีต `durian` ไม่รวมยอดภาค/ประเทศ รักษาขอบเขตห้าจังหวัดเดิม เพิ่มปีตามข้อมูลที่เผยแพร่จริง ไม่สร้างปีใหม่วันที่ 1 มกราคม

## การคัดกรอง

- ปี พ.ศ./ค.ศ. และ crop_year ตรงกัน ไม่รับปีอนาคต หน่วยตรงรายตัวแปร ไม่มีรายการซ้ำ
- ผลผลิตตัน พื้นที่ยืนต้นไร่ พื้นที่ให้ผลไร่ และผลผลิตต่อไร่ต้องมีค่าที่อ่านได้ ไม่ติดลบ ไม่แทน Missing เป็นศูนย์
- คำนวณ กก./ไร่ = ผลผลิตตัน × 1,000 ÷ พื้นที่ให้ผลไร่ ห้ามหารด้วยพื้นที่ยืนต้น ตรวจส่วนต่างจากค่าที่รายงานไม่เกิน 1 กก./ไร่เพื่อรองรับการปัดเศษ
- พื้นที่ให้ผลมากกว่าพื้นที่ยืนต้น ค่าปีเก่าที่ถูกแก้ไข หรือการเปลี่ยนเกิน 50% จากปีก่อน จะพักทั้งแถวใน `review` ไม่แก้ตัวเลขเงียบ ๆ เกณฑ์ 50% เป็นเกณฑ์ตรวจข้อมูลทางวิศวกรรม ไม่ใช่หลักฐานว่าผิดปกติทางเกษตรหรือข้อมูลผิด
- การเปรียบเทียบปีต่อปีใช้ปีติดกันเท่านั้น ฐานเป็นศูนย์หรือขาดปีไม่คำนวณเปอร์เซ็นต์
- ปีเก่าที่มีอยู่ยังแสดงจากชุดเดิม แม้แถวจาก OAE รุ่นใหม่ต้องพักตรวจ ตารางแสดง candidate/previous ใน API ให้เทียบได้

## ความน่าเชื่อถือและข้อจำกัด

ผ่าน QC หมายถึงโครงสร้าง หน่วย สูตร และความเปลี่ยนแปลงผ่านตัวกรองเท่านั้น **ไม่รับรอง Final Actual** ไม่มีการอนุมานวันเผยแพร่จาก data_date และไม่มีการรับรองความถูกต้องจากข่าวภัยพิบัติอัตโนมัติ ค่ารายงานทางการที่ยังพิสูจน์ Final Actual ไม่ได้จะยังระบุ unverified ไม่ใช้เพิ่ม Label ฝึกโมเดล

ไม่เปลี่ยน `production_annual.csv`, ข้อมูลต้นทาง, HTML ที่ฝังชุดข้อมูลเดิม, โมเดล หรือ replay เดิม ใช้ข้อมูลอัปเดตเฉพาะสถิติเชิงพรรณนาในหน้าผลผลิตและ CSV ที่ดาวน์โหลดจากหน้านี้เท่านั้น หน้าอื่นยังใช้ snapshot เดิม

เครื่องพัฒนาเก็บ `source.xlsx`, `catalog.json`, `validation.json` ใน `.build/oae_updates/<SHA256>/` และสถานะใน `status.json` ไม่เขียนทับต้นฉบับ ตรวจใหม่ด้วย `python tools/orchard_oae_update.py` (เคารพแคชเช่นเดียวกับเว็บ)

Vercel ใช้ `/tmp/durian_oae_updates` เป็นแคชชั่วคราวต่อ instance ไม่ใช่คลังรุ่นถาวร ยังไม่ได้เชื่อมการเก็บรุ่น OAE ใน Supabase หรือเปิด Cron จึงไม่อ้างว่ามีงานตรวจเบื้องหลังตลอดเวลา ถ้าต้องตรวจแม้ไม่มีคนเปิดเว็บและรักษาทุกรุ่นบนออนไลน์ ต้องต่อ scheduled job กับ persistent storage เพิ่ม ไม่ได้ Deploy/Push ในงานนี้

## ผลตรวจ 2 พฤศจิกายน 2569

OAE CKAN ตอบ HTTP 403 จากเครื่องนี้ เก็บและแสดงสาเหตุอย่างตรงไปตรงมา ไม่ข้ามข้อจำกัดและไม่อ้างว่าดึงปีใหม่สำเร็จ ทดสอบ workbook OAE เดิมด้วย parser จริงและข้อมูลทดสอบแยก: เพิ่มแถว ตรวจสูตร หน่วยผิด Missing ศูนย์จริง ซ้ำ ปีขาด ปีอนาคต ฉบับแก้ไข และแหล่งล่ม/แคช ไม่เปลี่ยนข้อมูลจริงเพื่อทดสอบ
