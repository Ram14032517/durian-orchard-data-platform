สถานะโค้ดขณะจัดทำอยู่บน branch codex/organize-project อ้างอิง commit ฐาน c99c26a การเปลี่ยนแปลงในเอกสารนี้ยังเป็นงานในเครื่อง ไม่ใช่ commit หรือการ push/deploy ใหม่ และไม่ใช่การสำรอง Git ทั้งโปรเจกต์

สิ่งที่เพิ่มและแก้ตามรอบงาน

20 ตุลาคม รวบรวมหลักฐาน GAP ห้าจังหวัด

รวบรวมข้อมูลจันทบุรี ศรีสะเกษ อุตรดิตถ์ สุราษฎร์ธานี และชุมพร แยกทะเบียน GAP ของกรมวิชาการเกษตร ทะเบียนเพื่อส่งออกจีน หลักฐานย้อนหลัง และสถิติพื้นที่ ไม่รวมเป็นจำนวนสวนประชากรเดียวกันโดยอัตโนมัติ Excel มีแหล่งอ้างอิง ข้อจำกัด และข้อมูลตรวจสอบเพื่อย้อนกลับไปดูที่มาได้

ข้อมูลค้นหา GAP มี 64,215 แถวส่งออกที่ครบถ้วน อ่านพิกัดทศนิยมได้ 34,743 แถว ต่อมาชั้นแผนที่รับแสดง 32,871 หมุดทะเบียนหลังใช้เงื่อนไขแสดงผล ตัวเลขทั้งสามหมายถึงคนละขั้นตอน ไม่ใช่จำนวนสวนที่ลงสำรวจยืนยันแล้ว รหัสทะเบียนต่างกันอาจอยู่ที่พิกัดเดียวกันหรือเกี่ยวข้องกับสวนเดียวกันได้

21 ตุลาคม เพิ่มชั้นหมุด GAP และเชื่อมพื้นที่ A กับ B

เพิ่มตัวกรองจังหวัด อำเภอ ธงคุณภาพพิกัด และช่วงวันที่ทะเบียน เลือกหมุดจากแผนที่หรือรายการที่ใช้คีย์บอร์ดได้ ระบบเก็บที่มาและพิกัดของทะเบียนที่เลือกเพื่อเรียกอากาศและจับคู่ชั้นดิน ไม่แทนตำแหน่งนั้นด้วยจุดกลางจังหวัดหรือกลางอำเภอ

การเลือกแปลงเป็น B ไม่เขียนทับ A หมุดรวมเมื่อซูมออกเป็นการลดความรกของหน้าจอ ไม่ใช่กลุ่มระดับความเสี่ยงโรค พิกัดทะเบียนยังไม่ได้ยืนยันภาคสนาม อากาศ NASA เป็นข้อมูลกริด และดินเป็นข้อมูลจากแผนที่ ไม่ใช่ค่าที่วัดโดยเซนเซอร์ในสวน

21 ตุลาคม ปรับหน้าตาและการเคลื่อนแผนที่

เพิ่มธีม Orchard Studio สีขาวและเขียว แยกแผนที่กับแผงรายละเอียด พับตัวกรองขั้นสูงและรายละเอียดดิน มีปุ่มขยายแผนที่เต็มหน้าต่าง รองรับหน้าจอแคบและการตั้งค่าลดการเคลื่อนไหว

ปรับการซูมและการย้ายไปจังหวัดหรืออำเภอให้มีการเคลื่อนต่อเนื่อง ยกเลิกการเคลื่อนก่อนหน้าหากเลือกเป้าหมายใหม่ และนำหมุดที่วาดแล้วกลับมาใช้แทนการสร้างใหม่ทุกครั้งที่แพน ไม่ได้วัดหรือรับรองจำนวนเฟรมต่อวินาที จึงไม่อ้างเปอร์เซ็นต์ความเร็วเพิ่มขึ้น

22 ตุลาคม คืนหน้าแรก IoT และเพิ่มชุดเอกสารนี้

คืนหน้าเปิดเป็น สวนของฉัน ทุกครั้งที่เปิดหรือ reload ตามพฤติกรรมเดิม และเอาการจำแท็บจาก orchard.workspace.v2 ออก เพื่อไม่ให้แท็บแผนที่ที่เคยเปิดค้างมาแทนหน้าแรกอีก ส่วนแท็บแผนที่และปุ่ม GAP ยังคงอยู่

แก้จังหวะเริ่มแผนที่เมื่อเปิดจากหน้า IoT ที่ซ่อนแผนที่ไว้ โดยไม่คำนวณมุมมองจากขนาดศูนย์ รอให้พื้นที่แผนที่มีขนาดจริง และใช้ความพร้อมของ DOM แทนการรอภาพหรือฟอนต์จากเครือข่ายทั้งหมด ไม่เปลี่ยนการเลือกอุปกรณ์หรือแหล่งข้อมูล IoT จากการแก้นี้

เพิ่มบันทึกฉบับ Markdown และ HTML พร้อมสำเนา Excel ในโฟลเดอร์เอกสารแนบ เพิ่มลิงก์จากหน้าเริ่มต้นและดัชนีคู่มือ และเพิ่ม regression tests ตรวจหน้าแรกและการแยกคำขอ IoT ออกจากพื้นที่บนแผนที่

Excel ที่แนบมีอะไรและเชื่อถือส่วนไหนได้

ไฟล์แนบมี 10 ชีตตามต้นฉบับ ได้แก่ สรุป ทะเบียนGAPสด ทะเบียนจีนสด ทะเบียนจีน2021 รายแปลงย้อนหลัง สถิติGAP ข้อมูลประกอบ แหล่งและคุณภาพ เกณฑ์การใช้ และตรวจสอบ โครงสร้าง สูตร ตัวกรอง และรูปแบบเดิมไม่ได้ถูกแก้ในรอบแนบเอกสารนี้

ทะเบียน GAP จากกรมวิชาการเกษตร ใช้อ้างอิงสิ่งที่ระบบทะเบียนรายงาน ณ snapshot ได้ แต่สถานะที่รายงานกับการประเมินวันออกและวันหมดอายุเป็นคนละหลักฐาน ไม่ได้รับรองความถูกต้องของพิกัดหรือสถานะล่าสุดด้วยการเปิดไฟล์ครั้งนี้ ค่าผลผลิตที่รายงานไม่มีปีเก็บเกี่ยวและวิธีวัดที่ยืนยัน จึงยังใช้เป็นผลผลิตจริงรายสวนต่อปีไม่ได้

ทะเบียนส่งออกจีน ใช้อ้างอิงการขึ้นทะเบียนตามชุดข้อมูลนั้น ไม่ยืนยันว่ามีการส่งออกจริงในปีใด ปริมาณกี่ตัน หรือมีผลผลิตจริงเท่าไร ไม่ใช้จำนวนทะเบียนแทนยอดขายหรือปริมาณส่งออก

ข้อมูลย้อนหลังและสถิติจังหวัดหรืออำเภอ ใช้ตามปี หน่วย ประชากร และขอบเขตที่ต้นทางกำหนด ไม่ใช้จำนวนผู้ผ่านอบรมหรือข้อมูลพืชทุกชนิดแทนสวนทุเรียนที่ผ่าน GAP และไม่ยกสถานะปีเก่ามาเป็นสถานะปัจจุบัน

สิ่งที่ยังไม่ยืนยัน คือการเป็นสวนไม่ซ้ำ ความถูกต้องภาคสนาม ผลผลิตจริงรายแปลง และผลตรวจโรคที่มีวันที่ ไม่มีคะแนนความเชื่อมั่นตัวเลขที่พิสูจน์แล้วสำหรับรายการเหล่านี้ ความน่าเชื่อถือด้านที่มาไม่เท่ากับความถูกต้องของทุกฟิลด์

แม้ไฟล์ลดข้อมูลส่วนตัวแล้ว พิกัดและรหัสทะเบียนยังอาจเชื่อมกลับไปหาสวนได้ ควรตรวจสิทธิ์ เงื่อนไขต้นทาง และความเหมาะสมก่อนแจกจ่ายไฟล์หรือเปิดพิกัดละเอียดบนเว็บสาธารณะ

สถานะโมเดลและการเตรียมทดลอง

รอบ GAP สร้างเพียงแผนเตรียมข้อมูล: มีจุดตัวแทน GAP 40 จุดและจุดอ้างอิงจังหวัดเดิม 5 จุด วางแผนงานขออากาศ 135 งาน แต่ยังไม่ได้ดาวน์โหลดอากาศตามแผนนี้ ยังไม่ได้ fit สร้าง prediction หรือสร้างคะแนนประเมินใหม่ train_eligible ยังคงเป็น false

หน่วยผลผลิตเป้าหมายยังเป็น 80 จังหวัด–ปี ระหว่าง 2010–2025 ไม่ใช่ผลผลิตของหมุด 32,871 จุด ห้ามคัดลอกผลผลิตจังหวัดหนึ่งปีไปทุกหมุดแล้วสุ่มแบ่ง train/test เพราะไม่ได้เพิ่มตัวอย่างผลผลิตอิสระ

โมเดลผลผลิต Ridge และ VPD เดิม กับโมเดลความชื้นดิน 6 ชั่วโมงไม่ได้ถูกแทนที่ด้วยงาน GAP หรือการแต่งเว็บ โมเดลความชื้นที่ตั้งไว้ยังเป็น persistence ซึ่งใช้ค่าปัจจุบันเป็นค่าอ้างอิงล่วงหน้า ไม่ใช่หลักฐานว่าโมเดลเรียนรู้ดีขึ้น และยังไม่มีโมเดลโรครายสวนที่ฝึกจากผลตรวจโรคจริง

ดังนั้นยังไม่มีเปอร์เซ็นต์ความแม่นที่เพิ่มจาก GAP คะแนนผลผลิตย้อนหลังที่เคยรายงานไม่ใช่ผลของงานเพิ่ม GAP นี้ การวัดประโยชน์ต้องทำการทดลองคู่เทียบบนจังหวัด–ปีเดียวกัน โดยตรึงวิธีและรายงานข้อจำกัดทะเบียนปัจจุบันเมื่อใช้แทนอดีต

ข้อขัดข้อง pipeline เดิมเรื่อง hash ของ CSV แบบ LF กับ CRLF ยังไม่ได้แก้ในรอบนี้ ไม่เปลี่ยน audit hash ปิดตัวตรวจ หรือ train ทับเพื่อให้ผ่าน ดูรายละเอียดและหลักฐานที่คู่มือ GAP

สิ่งที่คงไว้สำหรับ IoT เดิม

เส้นทางรับข้อมูลอุปกรณ์เดิมยังอยู่ใน iot/ และ api/ ไม่แก้ firmware ปลายทางรับข้อมูล Supabase schema หรือรหัสอุปกรณ์ ไม่เปลี่ยน API key ไม่ย้ายข้อมูล และไม่ส่งข้อมูลทดสอบเข้าอุปกรณ์หรือฐานข้อมูลจริง

หน้าเว็บยังใช้ /api/orchard-status และ /api/orchard-history ตามเดิม ประวัติอุปกรณ์เลือกด้วย ORCHARD_DEVICE_ID ทางเซิร์ฟเวอร์ ไม่เลือกด้วยจังหวัด A/B หรือรหัสหมุด GAP การสลับแผนที่จึงต้องไม่เปลี่ยนว่าอ่านข้อมูลของอุปกรณ์ใด

ผู้ใช้ยืนยันว่าใช้งาน IoT บนเว็บ cloud เดิม จึงคงระบบ cloud เป็นแหล่งใช้งานหลัก ไม่ย้ายการรับข้อมูลมา Mac API สถานะและประวัติบน cloud ยังอ่าน Supabase ตาม configuration เดิม ยังไม่ deploy รหัสรอบนี้ขึ้น cloud และยังไม่ได้ทดสอบการรับข้อมูลจริงบนระบบนั้นในรอบจัดทำเอกสาร การแก้หน้าแรกเกิดในโค้ดที่เครื่องนี้ ยังไม่ใช่การยืนยันว่าหน้าเว็บ cloud เปลี่ยนแล้ว

เมื่อเปิดบน Mac ผ่าน local server เดิม สถานะปัจจุบันอ่าน data/processed/orchard_live/live_report.json ส่วนประวัติอ่าน Supabase สองแหล่งนี้เป็นพฤติกรรมเดิม ไม่ใช่การใช้ทะเบียน GAP เป็นข้อมูล IoT

ในเครื่องนี้ไม่พบไฟล์สถานะดังกล่าว และ process local ยังไม่มีค่าตั้งค่า Supabase กับอุปกรณ์ จึงอาจแสดง “ยังไม่มี snapshot สวน” และอ่านประวัติไม่ได้ การคืนหน้าแรกแก้การนำทางแล้ว แต่ไม่ได้ทำให้ข้อมูลสดปรากฏขึ้นเอง ไม่คัดลอกข้อมูลวิเคราะห์เก่ามาปลอมเป็นข้อมูลสด และไม่เติมช่องว่างเป็นศูนย์

หากต้องการอ่าน Supabase บน Mac ต้องตั้งค่าฝั่งเซิร์ฟเวอร์อย่างปลอดภัยโดยใช้ SUPABASE_URL, SUPABASE_SECRET_KEY หรือ SUPABASE_SERVICE_ROLE_KEY และ ORCHARD_DEVICE_ID ตาม คู่มือการใช้งานเดิม ไม่วาง secret ลง HTML หรือส่งคีย์ในแชต และไม่ใช้ DEVICE_INGEST_KEY ของบอร์ดแทนสิทธิ์อ่านฐานข้อมูล การทำให้สถานะ local อ่านสดแทน snapshot เป็นการเปลี่ยนโหมดที่ต้องกำหนดให้ชัดก่อนทำ

ตรวจสอบแล้วและสิ่งที่ยังไม่ได้ทดสอบ

  • JavaScript ทั้งชุดผ่าน 57 กรณี รวมกรณีใหม่ที่หน้าเปิดเป็น IoT เปลี่ยน A/GAP แล้วไม่เปลี่ยนคำขอสถานะ ประวัติยังใช้เฉพาะช่วงเวลา และแผนที่รอขนาดที่มองเห็นจริงก่อนจัดมุมมอง
  • Python ชุดเอกสาร เว็บ GAP ชั้นข้อมูล ความเป็นส่วนตัว การเปิดรายงาน ประวัติ IoT และ current context ที่เรียกตรวจรวม 60 กรณี ผ่าน 56 กรณี อีก 4 กรณีประมาณการผลผลิตจังหวัดติดตัวตรวจ snapshot hash เดิม ไม่ใช่การเชื่อม IoT หรือฟังก์ชันเอกสารเสีย การตรวจใช้ข้อมูลจำลองหรือไฟล์ทดสอบ ไม่ใช่การยืนยันว่าบอร์ดส่งข้อมูลสดถึง cloud แล้ว
  • ตรวจ Safari หลัง build แล้วพบว่า reload เปิด สวนของฉัน จริง และแสดงข้อจำกัดตามต้นทาง คือไม่มี snapshot กับยังไม่ได้ตั้ง ORCHARD_DEVICE_ID ไม่แสดงค่าที่แต่งขึ้นแทนข้อมูลสด
  • ตรวจ Chrome จากหน้า IoT ไปแผนที่หลังแก้แล้ว แสดงหมุดสุราษฎร์ธานี 11,081 หมุดในขอบจอ รวมเป็น 17 กลุ่ม ส่วนการวาดครั้งแรกใน Safari ระหว่างการควบคุมอัตโนมัติยังยืนยันไม่ได้ พบว่า callback วาดเฟรมยังไม่ทำงานตามที่คาด จึงไม่อ้างว่าทดสอบ Safari ผ่านครบทุกฟังก์ชัน รอบแผนที่ก่อนหน้านี้ตรวจเลือก A/B ตัวกรองอำเภอ ล้อซูม ขยายหน้าต่าง และหน้าจอแคบใน Chrome แล้ว
  • Excel ผ่านการตรวจโครงสร้าง ZIP และ hash สำเนาต้องตรงกับต้นฉบับ ข้อมูลและสูตรไม่ได้ถูกเขียนใหม่ การตรวจครั้งนี้ไม่ได้ตรวจสอบใบรับรองปัจจุบันทุกแปลง
  • ชุดทดสอบ cloud ทั้งหมดไม่ได้ผ่านครบเพราะข้อขัดข้อง snapshot hash เดิมหนึ่งกรณี ไม่อ้างว่าการทดสอบทั้ง repository ผ่านทั้งหมด

  • .gitignore เพิ่มขอบเขตไฟล์ GAP และเอกสารแนบที่ไม่รวมในการเผยแพร่โค้ดโดยอัตโนมัติ

งานถัดไป

  1. ผู้ใช้ยืนยันแล้วว่าใช้ cloud เดิม หากต้องตรวจรุ่นที่ใช้งานจริงต่อ ให้ใช้ URL cloud เดิมเพื่อตรวจสถานะเซนเซอร์และเวลาวัดจากต้นทางนั้นก่อนเปลี่ยนหรือ deploy ไม่ต้องส่ง API key ในแชต
  2. หากต้องการใช้ Mac เป็นหน้าติดตามสด ให้ตั้งค่าฝั่งเซิร์ฟเวอร์และตกลงโหมดสถานะ local ก่อน โดยรักษาเส้นทางรับข้อมูลเดิม ไม่แก้ปัญหาด้วยการแทนค่าจากทะเบียนหรือข้อมูลย้อนหลัง
  3. ทบทวนพิกัดและความครอบคลุม GAP ก่อนขออากาศตามแผน จากนั้นทำการทดลองคู่เทียบ ไม่อ้างความแม่นเพิ่มจากจำนวนหมุดเพียงอย่างเดียว
  4. เก็บผลผลิตจริงรายสวน วันที่ตรวจพบและตรวจไม่พบโรค ภาพอาการ ระยะดอกและผล และการจัดการน้ำ เพื่อให้ตรงกับเป้าหมายป้องกันโรคในสวน
  5. เมื่อต้องการบันทึกงานรอบใหม่ให้สร้างเอกสารวันที่ใหม่ แยกสิ่งที่ทำแล้วกับข้อเสนอ และเก็บต้นฉบับกับหลักฐานไว้ ไม่เขียนทับคะแนนหรือสถานะเก่า

หลักฐานที่ใช้จัดทำ

  • คู่มือ GAP และการทดลองเชิงพื้นที่
  • แผนความพร้อมพยากรณ์และข้อจำกัดคะแนนเดิม
  • แนวทางโมเดลสวนและการเก็บผลตรวจโรค
  • คู่มือเชื่อมและใช้งานระบบเดิม
  • รายละเอียดและ hash ของ Excel แนบ

ตรวจเทียบโค้ดต้นทางกับ commit ฐานโดยไม่อ่านหรือแสดงค่า secret และไม่ติดต่อฐานข้อมูลอุปกรณ์จริง เอกสารนี้เป็นบันทึกสถานะ ณ วันที่ระบุ ไม่ใช่ใบรับรองคุณภาพข้อมูลหรือความแม่นของระบบ
