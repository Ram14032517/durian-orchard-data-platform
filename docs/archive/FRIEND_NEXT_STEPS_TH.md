## 3. ต้องแยก branch ไหม?

**ควรแยก branch ตามงาน และส่ง Pull Request กลับ main** เพื่อนควร clone ลงเครื่องตัวเอง ไม่ทำงานทับโฟลเดอร์ C:\project ของเจ้าของโดยตรง

```powershell
git clone https://github.com/Ram14032517/durian-orchard-data-platform.git
cd durian-orchard-data-platform
git switch -c codex/map-ui-qa
```

ถ้ามี clone อยู่แล้ว ให้ตรวจ `git status` ก่อน หากมีงานค้างให้เก็บงานของตัวเองก่อน ไม่ใช้ reset --hard จากนั้นจึง `git switch main` และ `git pull --ff-only origin main` แล้วสร้าง branch ใหม่

| ลำดับ | Branch ที่แนะนำ | งานและไฟล์หลัก |
|---|---|---|
| 1 | `codex/map-ui-qa` | ทดสอบ/แก้หน้าฤดูและหน้ารวม: `tools/five_province_seasons.html`, `tools/unified_orchard_map.html` |
| 2 | `codex/weather-api-tests` | ทดสอบ API/cache: `tools/serve_orchard_analysis.py`; เพิ่ม `tests/test_orchard_api.py` |
| 3 | `codex/phenology-evidence` | รวบรวมหลักฐานฤดู/เหตุการณ์: เพิ่ม `research_data/five_province_history/phenology_events.csv` และ `EVIDENCE_SOURCES_TH.md` |
| 4 | `codex/history-analysis` | วิเคราะห์เปรียบเทียบจากหลักฐานที่ตรวจแล้ว: `tools/build_history_notebook.py`, `tools/build_five_province_history.py` |

หากมีเพื่อนคนเดียว เริ่มลำดับ 1 ให้ผ่านและ merge ก่อน แล้วค่อยสร้าง branch งานถัดไป ไม่จำเป็นต้องเปิดครบสี่ branch พร้อมกัน หากหลายคนช่วยกัน ให้แบ่งเจ้าของไฟล์เพื่อไม่แก้ template เดียวกันพร้อมกัน

## 4. รันอะไร และต้องแก้ไฟล์ไหน?

ใช้ Python 3.10+ ใน environment ของตนเอง (อย่าคัดลอก `.venv` จากเครื่องอื่น)

```powershell
python -m pip install requests
python tools/serve_orchard_analysis.py
```

เปิดหน้ารวม:
http://127.0.0.1:8871/research_data/five_province_history/UNIFIED_MAP.html

เปิดหน้าฤดู 5 จังหวัด:
http://127.0.0.1:8871/research_data/five_province_history/SEASONS_MAP.html

ต้องเปิดเซิร์ฟเวอร์ค้างไว้ การเปิด HTML ตรง ๆ หรือ static server พอร์ต 8870 ไม่รองรับ API อากาศของหน้ารวม แผนที่พื้นหลัง/CDN และอากาศใหม่ต้องใช้อินเทอร์เน็ต

**แก้ template ใน tools ไม่ใช่แก้เฉพาะ HTML ที่สร้างแล้ว** หลังแก้ template ให้สร้าง output ใหม่:

```powershell

python tools/build_unified_orchard_map.py
git diff --stat
```

สคริปต์นี้สร้าง `UNIFIED_MAP.html`, `SEASONS_MAP.html`, ตารางจุดอ้างอิง และเขียน GeoJSON ดินใหม่ด้วย ตรวจ diff ก่อน commit ว่ามีแต่สิ่งที่ตั้งใจ ไม่ต้องดาวน์โหลด NASA ทั้งหมดซ้ำเพื่อแก้หน้าเว็บ

## 6. งาน API / cache

- เพิ่ม automated tests โดย mock NASA: missing -999, ช่วงวันผิด, พิกัดนอกขอบเขต, upstream timeout/error, cached response
- ทดสอบ live API ช่วงสั้น 1 จุด แล้วทดสอบซ้ำให้ได้ cache; บันทึก URL/วันดึงโดยไม่ต้องเรียกซ้ำมาก
- ตรวจ cache ของช่วงใกล้ปัจจุบัน: ตอนนี้ไม่มีอายุหมดอายุ อาจเก็บวัน missing ไว้ตลอด ต้องกำหนด refresh policy ก่อนเรียกว่าอัปเดตปัจจุบัน
- แสดง coverage ของฝน/อุณหภูมิ/ความชื้นแยกกัน ไม่บอกข้อมูลครบเพียงเพราะอุณหภูมิครบ
- ค่าอากาศเป็นกริด NASA POWER และวัน LST ไม่ใช่สถานีรายสวน; จุดใกล้กันอาจได้ค่าเดียวกัน
- เพิ่มวิธีรัน tests ใน README; อย่าคอมมิท cache ทุกครั้งโดยไม่ตรวจขนาดและความจำเป็น

## 7. หลักฐานที่ยังขาด — ไม่ใช่งานที่แก้ด้วยโค้ดอย่างเดียว

สร้าง `phenology_events.csv` โดยเสนอคอลัมน์:

```text
province_code,district,site_name,latitude,longitude,cultivar,
stage,event_start,event_end,published_date,date_precision,
evidence_type,source_url,source_title,retrieved_date,notes
```

- แยก `observed` (รายงานว่าเกิดจริง), `forecast` (คาดการณ์), `administrative_cut_date` (วันเริ่มตัดตามประกาศ), `backcast_scenario` (คำนวณสมมติ)
- วันที่เกิดเหตุไม่ใช่วันที่ข่าวเผยแพร่; ถ้ารู้แค่เดือนให้เก็บ precision ว่า month ไม่สร้างวันขึ้นเอง
- ไม่ทราบพิกัด/พันธุ์ให้เว้นว่าง ไม่ใส่พิกัดกลางจังหวัดแล้วเรียกว่าสวน
- ตรวจลิงก์รายงานเหตุการณ์ที่ hardcode ใน `tools/unified_orchard_map.html` และ `tools/five_province_history.html` ก่อนนำมาใช้วิเคราะห์
- ผลผลิต OAE ที่มีเป็นทุกพันธุ์ระดับจังหวัด ไม่ใช่หมอนทองทั้งหมด ไม่แจกยอดลงอำเภอหรือชุดดิน
- คุณสมบัติดินจากแผนที่ไม่ใช่ผลตรวจความอุดมสมบูรณ์ปัจจุบันของสวน และ polygon ดินไม่ยืนยันว่ามีทุเรียนปลูก

## 8. วิเคราะห์ต่อเมื่อหลักฐานพร้อม

เริ่มจากคำถามว่า “ฤดูเก็บเกี่ยวของ 5 จังหวัดเปลี่ยนอย่างไรในแต่ละปี และช่วงนั้นอากาศต่างกันอย่างไร” ก่อนสร้างโมเดลทำนาย

เปรียบเทียบผลผลิตรวมควบคู่พื้นที่ให้ผลและผลผลิตต่อไร่ แยกอากาศในช่วงที่มีหลักฐานระยะพืชจากอากาศเฉลี่ยทั้งปี ระบุ missing coverage และไม่สรุปสาเหตุจาก correlation ใช้การแบ่ง train/test ตามเวลาเมื่อพัฒนาโมเดล ห้ามใช้ข้อมูลหลังวันทำนายเป็น feature

ข้อมูลสวนสุราษฎร์ธานีใช้ตรวจ/เปรียบเทียบอากาศกริดกับสถานีสวนและการเปลี่ยนความชื้นดินได้: ใช้ outdoor temperature/humidity ไม่ใช้ค่าในบ้าน ตัดหรือ flag ช่วงอากาศค้างจาก gateway ตามหลักฐาน ไม่ลบดินที่ยังถูกต้องไปด้วย และเก็บ raw ต้นฉบับไว้

## 9. ส่งงานกลับอย่างปลอดภัย

ก่อน commit ให้ `git status` และ `git diff` แล้ว stage **เฉพาะไฟล์ของงานตนเอง** ตัวอย่างงาน UI:

```powershell
git add tools/unified_orchard_map.html tools/five_province_seasons.html research_data/five_province_history/UNIFIED_MAP.html research_data/five_province_history/SEASONS_MAP.html
git diff --cached --stat
git commit -m "fix: validate five-province map interactions"
git push -u origin codex/map-ui-qa
```

เปิด Pull Request ไป main พร้อมรายการที่แก้ วิธีรัน ผลทดสอบ และสิ่งที่ยังไม่ผ่าน ไม่ force-push main ไม่ commit `.secrets`, token, `.venv` หรือข้อมูลดินดิบไฟล์ใหญ่โดยไม่ตรวจ นโยบายสิทธิ์เผยแพร่ต้นทางต้องตรวจเพิ่มก่อนอ้างว่า dataset พร้อมตีพิมพ์

เกณฑ์รับงานรอบแรก: เพื่อน clone แล้วเปิดได้จริง เลือก 5 จังหวัด/ปีได้ ค่าหายไม่กลายเป็นศูนย์ มีอ้างอิงและข้อจำกัด และมีบันทึกทดสอบหน้าจอ+API ไม่ใช่แค่มีไฟล์ HTML
