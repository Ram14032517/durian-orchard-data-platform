ภาพรวมโปรเจกต์สวนทุเรียน

ระบบติดตามสภาพสวนด้วย IoT และงานศึกษาดิน–อากาศ–ผลผลิตใน 5 จังหวัด

สองสายงานที่สนับสนุนโครงงาน

1. เฝ้าระวังสวนจริง

เก็บข้อมูลดินและอากาศ ตรวจค่าขาดหรือค้าง และคัดช่วงที่ควรเข้าตรวจสวน มีโค้ด Gateway ระบบรับข้อมูล และ baseline ตรวจความผิดปกติ

ยังต้องเก็บอาการและผลยืนยันโรคของต้นจริงก่อนประเมินการทำนายโรค

2. ศึกษาข้อมูลระดับภูมิภาค

เปรียบเทียบ 5 จังหวัดผ่านแผนที่ กราฟอากาศ ชุดดิน และผลผลิต ทดลองโมเดลผลผลิตโดยแบ่งข้อมูลตามเวลา

ผลระดับจังหวัดใช้แทนสุขภาพหรือผลผลิตของต้นแต่ละต้นไม่ได้

เส้นทางข้อมูลในโค้ด Gateway ปัจจุบัน

ดิน RS485 + อากาศ Tuya→ESP32 Gateway→Supabase / Google Sheets→ตรวจคุณภาพ / วิเคราะห์

Gateway ยังดึงพยากรณ์ TMD และ NDVI ส่วน LoRa เป็นเส้นทางที่เอกสารระบุ แต่ sender หลักยังว่าง จึงยังยืนยันเส้นทาง LoRa จาก repository นี้ไม่ได้

จุดเริ่มอ่าน

  • คู่มือเริ่มต้น และ คู่มือ Mac
  • สถานะงานและข้อจำกัด
  • Notebook หลัก สำหรับอ่านและรันการวิเคราะห์
หน้าภาพรวมนี้เปิดเป็นไฟล์ HTML ได้โดยตรง ใช้ได้โดยไม่พึ่ง React หรือส่วนขยาย Canvas ส่วนแผนที่วิเคราะห์ให้เปิดด้วย 00_OPEN_REPORT.command เพื่อเริ่มเซิร์ฟเวอร์

ระบบ IoT ที่มีอยู่

  • Gateway อ่านเซนเซอร์ดินผ่าน Modbus และอากาศจาก Tuya
  • ส่งข้อมูลไป Supabase และ Google Sheets พร้อม event_id สำหรับกันข้อมูลซ้ำ
  • มีสคริปต์ตรวจช่วงขาดหาย ค่าอากาศค้าง และโมเดล median/MAD สำหรับคัดค่าผิดปกติ
  • โค้ด sender_1/sender_1.ino ยังมีเพียง setup/loop เปล่า

เปิดใช้งานบน Mac

  1. เปิดโฟลเดอร์โปรเจกต์ใน VS Code
  2. เลือก Terminal → Run Task → Durian: 01 เปิดแผนที่ (เริ่มตรงนี้) หรือดับเบิลคลิก 00_OPEN_REPORT.command ใน Finder
  3. เมื่อเปิด Notebook เลือก Python environment .build/national-analysis-venv/bin/python

อ่านคำสั่งและวิธีเลือก interpreter

สิ่งที่ควรทำต่อ

  1. ยืนยันฮาร์ดแวร์ที่ติดตั้งจริง และตัดสินใจว่าจะใช้ดินต่อ Gateway โดยตรงหรือผ่าน LoRa
  2. ทดสอบการอ่านเซนเซอร์และการส่งข้อมูลต่อเนื่อง พร้อมตรวจคุณภาพข้อมูลใหม่
  3. เก็บข้อมูลรายต้น การให้น้ำ และอาการจริงให้เชื่อมกับเวลาในระบบได้
  4. ทำ alert ที่บอกเหตุผลและสถานะเซนเซอร์ แล้วประเมินกับผลตรวจสวน
  5. ใช้ข้อมูล 5 จังหวัดเป็นบริบทวิจัยและผลทดลองที่อธิบายข้อจำกัดได้
