## ทดลองภูมิประเทศที่รันแล้ว (9 ตุลาคม 2569)

โค้ด `tools/durian_model/experiment_terrain_interaction.py` ใช้โครงสร้างเดิม แก้ inner split ให้ train < validation year และไม่เติม weather ที่ขาดเป็นศูนย์ ดึง SRTM30m 90 samples (10 พิกัดผู้ใช้ × 3×3 patch) จาก Open Topo Data เก็บ raw/cache `research_data/five_province_history/terrain_srtm30_samples.json` และตาราง `terrain_selected_points.csv` เป็น proxy รอบพิกัด ไม่ใช่ค่าเฉลี่ยอำเภอ/สวนให้ผล เฉลี่ยสองจุดต่อจังหวัดด้วยน้ำหนักเท่ากัน ไม่มีน้ำหนักพื้นที่ให้ผล ยังไม่ยืนยันว่าพิกัดเป็นตัวแทนสวนจริง ตัวเลข elevation/slope ที่ผู้ใช้ส่งเก็บแยกเป็น unverified scenario ไม่อ้างว่าเป็น DEM ที่ตรวจแล้ว

84 configs, 9 policies, 405 paired prediction rows ปี 2017–2025 ผล MAE/RMSE กก./ไร่: เดิม 190.87/243.42; อากาศสั้น rx7+hot38 179.94/232.89; supplied-main 179.42/228.48; supplied-interaction 177.46/229.76; SRTM-main 191.91/244.41; SRTM-interaction 184.21/237.27; province-weather diagnostic 198.28/253.89; inner-selected รวม scenario 183.54/234.58; evidence-selected ไม่รับ scenario 182.42/234.71 ภูมิประเทศ SRTM ยังไม่ชนะ weather control และ terrain คงที่ซ้ำเชิงเส้นกับ province indicators จึงไม่อ้าง causal soil/groundwater effects

อากาศลด MAE 5.73% แต่ descriptive bootstrap −12.49% ถึง 14.94% คร่อมศูนย์ นโยบาย evidence-selected ลด 4.43% ช่วง −7.82% ถึง 12.20% คร่อมศูนย์เช่นกัน ไม่ใช่ new independent holdout หลักฐานอยู่ `research_data/five_province_history/training/terrain_results.json` และ CSV summary/predictions/tuning; คู่มือ `tools/durian_model/README_TH.md` ตัวทำนายแยก `terrain_candidate_model.json` final refit ใช้ inner evidence-only เลือก baseline 140 วัน alpha1; ไม่ใช้กลุ่ม supplied ที่คะแนน test ดูดีที่สุด ช่องทาง `--predict-input` รับเฉพาะ complete-stage input ตาม template อายุ/ฤดูตรง contract ไม่มี target และระบุผลเป็น exploratory conditional estimate ไม่ใช่ live forecast ไม่เปลี่ยนโมเดลหลัก PDF/เว็บ และไม่ได้ commit/push

บันทึก 8 ตุลาคม 2569 ใช้คู่กับ [แผนงานเชิงพื้นที่](../research/spatial/RESEARCH_PLAN_SPATIAL_SOIL_WEATHER_YIELD_TH.md) และตรวจไฟล์จริงก่อนแก้ไข สถานะ Git ในเอกสารหรือข้อความเก่าอาจเปลี่ยนแล้ว

## ผลทดลองล่าสุด: ฤดูหลักและระยะปรับตามภูมิอากาศ (9 ตุลาคม 2569)

ต่อมาทดสอบ Dry Trigger ตามข้อเสนอจำกัดฤดู/ตรวจฝนหลงฤดูใน `tools/durian_model/experiment_dry_trigger.py` ใช้ฟีเจอร์เดิมทั้งหมดคำนวณตามหน้าต่างใหม่ (รวม VPD/แสง) 36 configs: MAE เดิม 190.87; dry 211.27; dry+reset 202.30; inner-selected 191.48 กก./ไร่ จึงไม่เปลี่ยนโมเดลหลัก Trigger คือวันแรกที่ฝนเฉลี่ย 15 วัน <1 แล้ว +50 วัน; reset ถ้ามีฝน >25 มม. t..t+30; จำกัดเริ่มค้น Dec1/Jan15 ตามภาค; จับคู่กับ cohort anchor จากฤดูปีฝึกภายใน ±30 วัน ถ้าไม่มี/อยู่นอกช่วงให้ fallback ชัดเจน แบบ dry/reset มี fallback ประมาณ 53–54% ของ cohorts ข้อมูลขาดไม่ถือเป็น no-trigger ผล/context/provenance ใน `training/dry_trigger_*` ใต้ `research_data/five_province_history/` วันที่นี้เป็น estimated/proxy ไม่ใช่ surveyed ไม่เพิ่มแขนสำรวจที่ไม่มีข้อมูล ไม่ตัดอุณหภูมิจาก predictors ไม่ถือว่าฝน reset ทำให้ตาดอกฝ่อจริงตามหลักฐานภาคสนาม

ล่าสุดทดสอบ critical window วัน 30–50 รวมปลายทั้งสองด้าน ใน `tools/durian_model/experiment_critical_window.py` เพิ่มร้อน >38°C, CDD, ฝน >=10 มม. หลังแห้ง 7 วัน และ heat × CDD โดยไม่บังคับทิศทาง MAE: เดิม 190.87; critical 197.26; interaction 194.22; critical+ฝนหนัก 189.38; inner-selected 192.87 กก./ไร่ ชุดที่ดีที่สุดลด MAE เพียง 0.78% แต่ RMSE สูงขึ้น และช่วง bootstrap คร่อมศูนย์ ทุกนโยบายปี 2024/final 2026 เลือกกลับ baseline อายุ 140 alpha 1 จึงไม่แก้ overprediction ปี 2024 ผลใน `training/critical_window_*` ใต้ `research_data/five_province_history/` ไม่ทับงานเก่า ไม่มีอายุต้นในโมเดล และ `local_age` เป็นชื่อวิธีปรับหน้าต่างอายุผล ผลทดลองเป็นความสัมพันธ์เชิงทำนาย ไม่ใช่หลักฐานยืนยันการร่วงจากความร้อนหรือฝน

รอบต่อมา ผู้ใช้ให้ลองปรับจากการตรวจพื้นที่ที่ทำนายผิด: เพิ่ม shock features ใน `tools/durian_model/experiment_weather_shocks.py` แยกจากการปรับอายุ ENSO เพื่อไม่ปนผล ใช้อากาศเดิม ไม่มีข้อมูลน้ำต้นทุน/ชลประทานหรือรายงานความเสียหายใหม่เข้าฝึก ร้อน–ฝนทิ้งช่วง MAE 193.03; ฝนหนักสะสม 3/7 วัน 184.01; รวม shocks 186.21 เทียบเดิม 190.87 กก./ไร่ แต่ inner validation เลือกทุกชุดเองได้ 193.99 (แย่กว่าเดิม) และ final refit เลือก baseline เดิม อายุ 140 alpha 1 ชุดฝนหนักลด 3.59% มีช่วง bootstrap −13.83% ถึง 11.84% คร่อมศูนย์ ชุมพร/ศรีสะเกษแย่ลง จึงยังไม่แทนโมเดลหลัก ผลแยกใน `research_data/five_province_history/training/weather_shock_*` และคู่มือ `tools/durian_model/README_TH.md` การทดลองนี้ไม่พิสูจน์ว่าภัยแล้ง/น้ำท่วมเป็นสาเหตุของ residual

## แผนต่อ: ผลผลิตรวม ถ่วงช่วงอายุผลตามพันธุ์ (9 ตุลาคม 2569)

ผู้ใช้ชี้แจงต่อจากคำว่า "เฉพาะหมอนทอง" ว่าต้องการใช้พันธุ์ที่ปลูกมากและส่วนผสมพันธุ์ของแต่ละจังหวัดเป็นตัวแทนระยะผล จึง **คง target ผลผลิตทุเรียนรวมต่อพื้นที่ให้ผล** และปรับ weather features ตามอายุของแต่ละพันธุ์ ไม่ต้องสร้าง target แยกพันธุ์จากยอดรวม ข้อชี้แจงนี้แทนข้อจำกัดหมอนทองอย่างเดียวในรอบก่อน

- ให้ `w(i,t,k) = พื้นที่ให้ผลพันธุ์ k / พื้นที่ให้ผลทุเรียนรวม` ของจังหวัด i ปี t ไม่เฉลี่ยทุกพันธุ์เท่ากัน และไม่ใช้พื้นที่ปลูกใหม่ที่ยังไม่มีผล ถ้ามีเพียงพื้นที่เก็บเกี่ยว ให้เก็บชื่อตัวหารตามต้นฉบับและตรวจนิยามก่อนถือว่าเท่ากับพื้นที่ให้ผล
- อายุเฉลี่ยเชิงสรุปคือ `A(i,t) = sum_k w(i,t,k) * A(i,t,k)` โดย `A(i,t,k)` เป็นอายุที่มีหลักฐานหรือสมมติฐานทดลองตามพันธุ์และอากาศปีนั้น ไม่ใช้ค่าคงที่ภูมิภาคที่ไม่มีการตรวจสอบเป็นความจริง
- สำหรับโมเดล ให้คำนวณอากาศตามช่วงย้อนหลังของแต่ละพันธุ์และฤดูของพันธุ์นั้นก่อน แล้วถ่วง features ด้วย w ไม่ตัดอากาศเพียงช่วงเดียวจากอายุเฉลี่ย เพราะอาจกลบเหตุร้อน/ฝนสั้นที่เกิดคนละระยะผล การถ่วงด้วยพื้นที่เป็น proxy ของการรับอากาศ ไม่ใช่สัดส่วนผลผลิตที่เท่ากันทุกพันธุ์
- ห้ามใช้สัดส่วนผลผลิตจริงรายพันธุ์ของปีทดสอบเป็นน้ำหนักทำนายผลผลิตปีเดียวกัน หากใช้สัดส่วนพื้นที่ของปีนั้นย้อนหลัง ให้ระบุว่าเป็นการวิเคราะห์แบบมีเงื่อนไขบนพื้นที่ที่ทราบแล้ว ไม่อ้างว่าเป็น forecast ที่รู้ข้อมูลนั้นล่วงหน้า
- ถ้ามีเพียงชื่อพันธุ์หลัก ไม่มีตัวเลขสัดส่วน ใช้เป็น `dominant_cultivar_proxy` ในการทดลองความไวได้ แต่ห้ามบันทึกเป็น 100% ของพื้นที่จริง หรืออ้างว่าได้ค่าเฉลี่ยพันธุ์ที่วัดครบ ปีที่ไม่มีสัดส่วนให้คง unknown ไม่คัดลอกสัดส่วนปี 2568 ไปทุกปีโดยเงียบ ๆ หากทดสอบ static composition ต้องระบุเป็น scenario และแยกจากผลใช้ข้อมูลปีตรงกัน
- หลักฐานเบื้องต้น: แผนจันทบุรีระบุหมอนทองเป็นพันธุ์นิยม แต่ไม่มีสัดส่วนครบรายปี (https://www.opsmoac.go.th/chanthaburi-strategic-files-442791791821); สุราษฎร์ธานีฉบับปี 2569 ระบุหมอนทองเป็นพันธุ์ที่นิยมปลูกมากที่สุด (https://www.opsmoac.go.th/suratthani-dwl-files-481091791081); ข่าวศรีสะเกษปี 2565 ระบุหมอนทองเป็นพันธุ์นิยม (https://doaenews.doae.go.th/archives/13228) ส่วนชุมพรยังไม่ได้ตรวจตารางยืนยันสัดส่วนรายปีในรอบนี้ ข้อมูลเหล่านี้ไม่ยืนยันว่าอันดับ/สัดส่วนคงเดิมทุกปี 2010-2025
- อุตรดิตถ์ ตารางแยกพันธุ์ปี 2568 ที่ตรวจไว้ด้านล่าง มีพื้นที่เก็บเกี่ยวรวม 44,669 ไร่: หมอนทอง 72.5649%, หลงลับแล 6.0243%, หลินลับแล 1.3141%, พื้นเมือง 20.0967% เป็นการหารพื้นที่เก็บเกี่ยวในตารางเดียวกัน ไม่ใช่ส่วนแบ่งผลผลิต ไม่แทนค่าชุดเดิมของ สศก. กลุ่ม "พื้นเมือง" มีหลายพันธุ์ จึงยังไม่มีอายุผลเดียวที่ยืนยันได้และห้ามตัด 20.0967% นี้ทิ้งแล้ว normalize พันธุ์ที่เหลือเป็น 100%
- งานวิจัยกรมวิชาการเกษตรเรื่องหลงลับแล/หลินลับแล (https://info.doa.go.th/research/index.php?act=view_detail&id=5299) รายงานว่าผู้สำรวจส่วนหนึ่งใช้เกณฑ์นับวันหลังดอกบาน 100-110 วัน ไม่ใช่ค่ามาตรฐานที่วัดครบทุกพื้นที่/ปี หรือการยืนยันช่วงดังกล่าวให้หลินลับแลโดยอัตโนมัติ

ข้อมูลส่วนผสมที่คำนวณได้ถูกเก็บใน `production_source_review.json` เพื่อทวนหลักฐานเท่านั้น ยังไม่ join เข้า training หรือเปลี่ยนโมเดล Ridge เดิม การทดลองต่อจะเทียบ (1) ระยะคงที่เดิม (2) พันธุ์หลักเป็น proxy (3) ส่วนผสมพันธุ์ตามข้อมูลที่มี และ (4) ส่วนผสมที่ปรับระยะตามอากาศ โดย tune จากปีเก่ากว่าปีทดสอบและประเมินบนแถวเดียวกัน

ลำดับทำต่อ:

1. รวบรวมจังหวัด/อำเภอ-ปีที่มี **พื้นที่ให้ผลหรือเก็บเกี่ยวแยกพันธุ์** และยอดรวมที่นิยามตรงกัน พร้อมพันธุ์ หน่วย URL หน้าเอกสาร วันข้อมูล และ actual/forecast/unknown ใช้เพื่อถ่วง features ไม่กระจายยอดทุเรียนรวมด้วยสัดส่วนพันธุ์ไปสร้าง target ไม่ถือว่าพื้นที่ GAP เท่ากับพื้นที่ให้ผลทั้งหมด
2. ใช้ปฏิทินเก็บเกี่ยวแยกพันธุ์ที่ยืนยันได้ ถ้ามีเพียงฤดูทุเรียนรวม ให้ติดป้ายเป็น proxy แยกต่างหาก ไม่ถือว่าเป็นวันดอกบานจริงของแต่ละพันธุ์
3. ตรวจอุณหภูมิ ฝน และรังสีแสงในช่วงก่อนเก็บเกี่ยวของจังหวัดนั้น เปรียบเทียบกับประวัติพื้นที่เดียวกันที่มีเฉพาะปีฝึก ป้ายร้อน/เย็น/เปียก/แห้งเป็นความเบี่ยงเบนจากข้อมูลพื้นที่ ไม่ใช่ประกาศภัยพิบัติหรือป้าย El Niño/La Niña ทั้งประเทศ
4. ทดลองช่วงระยะคงที่เทียบระยะที่ปรับจากอากาศ โดยการขยับ 0/5/10 วันเป็น **สมมติฐานเพื่อทดสอบ** ไม่ใช่ค่าความจริงทางชีววิทยา ห้ามล็อกว่าร้อนต้องสั้นลงเท่ากันทุกจังหวัด/ปี เลือกสูตร/ช่วงวัน/พารามิเตอร์ด้วยปีฝึกและ validation ที่เก่ากว่าปีทดสอบเท่านั้น ไม่ใช้ยอดผลผลิตหรือสัดส่วนเก็บเกี่ยวของปีทดสอบเลือกช่วงย้อนหลัง
5. รายงาน MAE/RMSE รายจังหวัดและรายปีบนแถวเดียวกัน พร้อมเทียบการขยายช่วงอายุคงที่เพื่อแยกผลของ search space ออกจากผลของการปรับตามอากาศ ไม่แทนโมเดลเดิมจนกว่าจะมีผลจริง; อายุที่ช่วยทำนายได้ไม่เท่ากับอายุผลที่วัดได้ ต้องใช้บันทึกดอกบาน/ตัดผลสอบเทียบหากจะอ้างอายุผลจริง รวมทั้งรายงาน coverage ของส่วนผสมพันธุ์และปีข้อมูลของน้ำหนัก

NASA POWER ที่มีอยู่เป็นหนึ่งจุดอ้างอิงต่อจังหวัด ยังไม่ใช่อากาศเฉลี่ยถ่วงด้วยพื้นที่สวนทุเรียนที่ให้ผลแยกพันธุ์ และช่วงปีเดิม 2017-2025 ถูกใช้สำรวจแล้ว ไม่ใช่ชุดทดสอบใหม่อิสระ

### ตัวเลือกพื้นที่และหน้าจอเปรียบเทียบ (ต่อรอบ UX)

- ตัวเลือก A/B แยกจังหวัด อำเภอ หน่วยดิน อยู่ในแผงขวา แผนที่ใช้พื้นที่เต็มฝั่งซ้าย; จอแคบเรียงลงด้านล่าง B เริ่มว่างและพับไว้จนกดเพิ่มพื้นที่เปรียบเทียบ เมื่อพับ B เปลี่ยนเป้าหมายคลิกแผนที่กลับ A แต่ยังรักษา B สำหรับกราฟ ปุ่มสลับรักษารายละเอียดพื้นที่และล้างผลอากาศเก่าก่อนโหลดใหม่ พิกัดซ้ำไม่สร้าง B
- ปุ่มซูม A/B ระบุว่าการกดจังหวัด/หน่วยดินบนแผนที่จะเปลี่ยนฝั่งไหน แผนที่ fitBounds ตามจังหวัดหรือหน่วยดินจริงทันที มีโหมดเห็นทั้งคู่ ไม่คัดลอก A เป็น B อีกแล้ว
- แถบข้อมูลสลับหัวข้อในช่องเดิม: อากาศ A/B, ข้อมูลดิน, ผลผลิตจังหวัด, ฤดู/รายเดือน, ดาวน์โหลด/หลักฐาน ตัวเลือกพื้นที่รักษาสถานะเปิด/ย่อเมื่อสลับหัวข้อ
- ผลผลิตรายปี/เดือนที่มีถึง 2568 มาจาก XLSX สศก. ใน `research_data/external/oae_2026-09-17/` ตาม `SOURCE.md` ไม่ใช่ PDF สุราษฎร์ฯ กรกฎาคม 2567 หน้าแคตตาล็อกระบุถึง 2567 ต่างจากแถวในไฟล์ ต้องรักษาความต่างนี้และไม่ยืนยันยอดปิดโดยไม่มีหลักฐาน ห้ามเลื่อนตัวเลขไปปี 2566 เพียงเพราะเอกสารอีกฉบับมีข้อมูล ณ พ.ย. 2566
- หน้าเตือนเมื่อเปิดแบบ file:// หรือเซิร์ฟเวอร์ไม่มี `/api/project` ให้ใช้ `00_OPEN_REPORT.cmd` ไม่ใช้ `python -m http.server` แทน API โครงการ
- เพิ่มการทดสอบ `tests/test_area_comparison.js` สำหรับความเป็นอิสระ A/B พิกัดซ้ำ การล้าง/โฟกัส race การโหลดชั้นดิน และการจับคู่ปีผลผลิตที่ตรงกัน
- ใช้ดีไซน์ Swiss: พื้นขาว เส้นแบ่งบาง ตัวอักษรอ่านชัด สีเข้มเฉพาะปุ่มโหลดข้อมูล แยกชิปจังหวัดออกจากแท็บเนื้อหา ไม่ใช้ป๊อปอัปดินขนาดใหญ่ รายละเอียดและชื่อเต็มของรหัสหน่วยดินอยู่ในแผงเลือกพื้นที่ ดาวน์โหลดจัดเป็นกริดเดียวกัน ไม่เพิ่มไลบรารีหน้าเว็บ
- ตรวจจริงที่ 1440 และ 360 พิกเซล: ฟอร์ม B ไม่ล้นขวา, ปุ่มจังหวัดครบ 5 แห่ง, เลือก/สลับ/ล้าง B, เปลี่ยนกราฟฝน และส่งออกอากาศ A/B เดือนกรกฎาคม 2568 ได้ 62 แถวจาก API จุดที่เลือก ไม่มีการเทรนโมเดลใหม่หรือยืนยันยอดผลผลิตขั้นสุดท้ายเพิ่ม

### การย่อฟอร์มและแยกข้อมูลดินตาม UX review
